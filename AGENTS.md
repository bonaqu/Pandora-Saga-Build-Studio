# Pandora Saga Build Studio — актуальные правила разработки

> Это **действующие** ограничения. Исторические решения и прежние инструкции, включая отменённые, сохранены без сокращений в [архиве AGENTS](docs/history/agents/README.md). При противоречии приоритет имеют последний явный запрос владельца, действующий код и текущие документы, **не** старые архивные релизные записи.

## Процесс работы и выпуск

- Работать крупными связанными пакетами, исправлять причины, переиспользовать код и убирать мёртвые пути. Не открывать отдельный PR ради одной текстовой строки или одного regex-теста. Не заявлять о полной безошибочности без доказательств.
- Основная ветка — `bonaqu_projects`; защищённый GitHub Ruleset требует `Unit regressions and release consistency` и `browser` на **точном** HEAD PR. Для JS/gameplay изменений нужен полный реальный Chromium, полный Node, release/source/asset/locale audits. После merge — GitHub Pages, Worker и каталог D1 **только чтение**. Не объединять pending/failed PR.
- Проверки запускаются на PR и публикации, без периодических cron. Для диагностики одного дефекта сначала профильный тест / browser `--only`, затем полный обязательный CI. Не дублировать тестовые entrypoints и не заменять живую регрессию поиском строки.
- Согласованное обновление версий — `scripts/release-version.mjs`: `package.json`, `site-version.json`, `index.html`, JS/CSS cache keys, OG/X-превью, `ROADMAP.md`, `CHANGELOG.md`. Историю релизов хранить в `docs/changelog/`, не раздувать корневые README/ROADMAP/CHANGELOG.
- Дополнительно: [операционные правила](docs/REPOSITORY_OPERATIONS_AND_FAST_DELIVERY.md), [архитектура](docs/STUDIO_ARCHITECTURE.md), [UX](docs/APPROVED_UI_UX_GUIDELINES.md).

## Источники данных, D1 и сохранения

- **Публичный сайт работает только после полной проверки актуального снимка Cloudflare D1.** Нет публичного offline/archive fallback, Service Worker-кэша каталога или расчётов на неподтверждённых данных. `localhost`/`127.0.0.1` — изолированные тестовые fixture-среды, не альтернативный источник для игроков.
- Первичный запуск и повторное подключение проверяют целостность и одинаковый snapshot каталога, редакторские RU/EN overrides и обязательные данные. При ошибке — блокирующий `inert`-экран, даже во время анимации закрытия. Сохранять текущего героя и библиотеку; не объявлять запись успешной, если `localStorage` отказал. При новом снимке — явное безопасное обновление, без потери текущих правок. [Подробный контракт](docs/ONLINE_ONLY_D1_RECOVERY.md).
- Гостю доступен текущий редактор персонажа без сохранённой библиотеки; библиотека, сравнение, публикация/открытие чужих ссылок требуют аккаунта. Не возвращать перенос исторических гостевых билдов. Не смешивать данные аккаунтов, не отправлять несохранённого героя в D1 автоматически.
- Обновление игрового каталога: D1 — источник опубликованных игровых записей; GitHub JSON сам по себе не означает публикацию. CAS-приёмка/полная staging-сверка/публичный readback 16 наборов — обязательны для **одобренной** конкретной записи. Не запускать production D1 writes без явного разрешения на объём изменений. Защищённый GitHub Actions доступ к D1 существует; не утверждать обратное без проверки. [Процедура](docs/VERIFIED_D1_PUBLICATION_PATH_2026-11-17.md).
- Не ослаблять серверную проверку аккаунтов и owner-токена ради UX. Не прятать реальную проблему под «сохранено», не перезаписывать черновик при неуспешном CAS/сети.

## Игровые расчёты и Книга героя

- **Не требовать тестов или снимков из запущенной игры.** Сопоставлять актуальные OS API/каталог/D1 с исходниками Remaked/Old Simulator; математические стадии исторической модели применять только если они совместимы с актуальным OS-вектором. Не использовать устаревшие числа и не выдумывать коэффициенты, округление, длительность, попадание, конечный урон, стаки или вероятность из одних `EP_*`/FV полей. Сомнения фиксировать в issue/исходных аудитах, не заявлять моделируемые значения серверно подтверждёнными.
- Книга героя показывает только результаты и применимые числовые эффекты **текущего** билда: восстановление, атаку, защиту, доступные собственные умения и внешние усиления для **этого** героя. Не создавать в Книге каталог умений, рецепты, крафт/материалы, монстр-picker или служебные объяснения. Справочная информация, материалы, ловушки и игровые источники — в Энциклопедии.
- «Усиления союзников» и «Усиления жреца» исходят от **других** персонажей, а текущий герой — получатель. Сохранять доступные внешние бафы, без смешивания умений самого героя и чужих эффектов. Точные подтверждённые формулы — в [матрице](docs/ALLY_BUFF_FORMULA_MATRIX.md), реестре [формул](docs/REMAKED_FORMULA_INVENTORY.md) и source-gated моделях.
- Не перезаписывать исходные RU/EN имена, ID умений и предметов, slot capacities/души на основании догадок. Любое изменение каталога проходит semantic/replay/source validation. #615 закрыт как выполненный этап, но это не доказательство абсолютной совместимости с реальным сервером.

## UI/UX, локализация, редактор владельца

- Пользовательский интерфейс: компактность, понятные действия, оригинальные локальные игровые изображения, общие SVG, правильный порядок действий ПКМ, без лишних рамок и технических комментариев. Гость не видит кнопок админки, служебных D1/API/CAS сообщений и скрытых редакторских подсказок.
- Во всех оснащаемых слотах оружия, щита, шлема, брони, перчаток, штанов, обуви и пояса показывать «Управление душами», включая 0 слотов; при 0 показывать понятную причину с типом вещи, вставку запрещать. Не создавать эту вкладку для неоснащаемых душами слотов.
- Редактируемые авторские RU/EN названия и подсказки имеют стабильные `guideedit.book.*` ключи и сохранение в D1 overrides через CAS/Undo, с компактным карандашом/двойным кликом и F2/Enter/Esc. **Тексты по умолчанию могут оставаться в JS**, в D1 сохраняются изменения владельца. Не сохранять в overrides пароли, токены, данные аккаунта, серверные ошибки, расчётные коэффициенты, игровые ID, неконтролируемую разметку. #390 по полному охвату ещё открыт.
- При повторной отрисовке не заменять активный `contenteditable`, не перезаписывать неизменённые `textContent`/ARIA/`dataset`. Общие owner DOM-helpers и общие пиктограммы обязательны; права owner проверяются Worker, а не только скрытым способом открытия панели.
- Менеджер обновлений обязан проверять **одинаковую** безопасность ручного и автоматического обновления: D1-гейт, фокус/незавершённые поля, модальные операции, аккаунт/owner. Ни один клик обновления не должен случайно вызывать `blur` и owner CAS. Проверки версий не должны дублироваться, таймаут распространяется на JSON.
