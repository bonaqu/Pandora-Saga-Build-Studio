# #476 — Проверяемый реестр трёх неоднородных EP-семейств

Это **отчёт об исходных данных**, а не подтверждение результатов игрового клиента или формул нанесённого урона. Он строится из закреплённого `data/os/skills.json` и не обращается к production D1.

## Воспроизведение

```bash
node scripts/audit-os-focused-ep-evidence.mjs
node scripts/audit-os-focused-ep-evidence.mjs --all
node --test tests/os-focused-ep-evidence-476.test.mjs
```

Первая команда выдаёт JSON-сводку по формам и знаковым вариантам. `--all` дополнительно возвращает каждую исходную запись: ID и название умения, индекс эффекта, тип, `learnable`, ключи классов, направление, `fv1/fv2`, соседние EP и `damage.kernel` (если есть). Ключи классов **не доказывают**, что конкретный герой удовлетворяет требованиям для изучения. Все выводы имеют статус `source-shape-only`.

## Исходный снимок и границы доказательства

- Текущий GitHub `data/os/skills.json`: blob SHA `ee7cd260b633e471614df300570edaf85486c8ef`.
- На данном снимке: 571 записей умений, 1 076 исходных эффектов, 283 уникальных `EP_*`; эти значения меняются при законном обновлении игрового каталога.
- Исторический `Pandora-Saga-Simulator-remaked/js/calc.js`, blob SHA `10422f21b61acba0e2c69f17f65e57a2230b84bc`, **не содержит прямых ссылок на имена `EP_*`**. Старые общие формулы сами по себе не позволяют установить роль каждого текущего `fv1/fv2`.

| Семейство | Эффекты на закреплённом снимке | Направления | Различные формы |
|---|---:|---|---:|
| `EP_ONHIT_DAMAGE_SCALE` | 29 | CASTER 28, TARGET 1 | 5 |
| `EP_TOGGLE` | 21 | CASTER 10, TARGET 11 | 5 |
| `EP_TOHIT_CONST` | 13 | CASTER 2, TARGET 11 | 5 |

Форма кодирует только направление и **индексы ненулевых позиций**. Знаковый вариант дополнительно фиксирует каждый `+`, `-` или `0` в восьми исходных ячейках, не присваивая им игровые единицы измерения.

## Конкретные проверяемые различия

- **On-hit:** `100101001` («Беспощадный удар») имеет `EP_ONHIT_DAMAGE_SCALE` CASTER `fv1=[0,0,0,25]` и отдельно `EP_TOHIT_CONST` CASTER `[0,0,100,50]`. `121703001` («Тройной укол») содержит `EP_ONHIT_DAMAGE_SCALE` **TARGET** `[0,0,0,-25]`. Применять единый множитель к двум направлениям нельзя без подтверждения механики.
- **Toggle:** `420002001` («Магический щит») содержит `EP_TOGGLE` TARGET `fv1=[0,0,0,0]`, `fv2=[0,0,0,0]` рядом с `EP_MANA_SHIELD`. У `213605001` («Точная стрельба») `EP_TOGGLE` TARGET `fv1=[0,0,0,3]`, `fv2=[0,0,-1,2]`. Нулевой вектор переключателя не означает отсутствие действия других эффектов того же умения.
- **To-hit:** `100054001` («Сосредоточенность») содержит `EP_TOHIT_CONST` TARGET `[0,0,0,100]`; `260004001` («Путающая рука») — TARGET `[0,0,-50,-30]`; `340001003` («Песнь поэта», внутреннее действие) — TARGET `[13,0,13,4]`. Наличие отрицательных значений не доказывает конкретное изменение конечного шанса попадания или стадии округления.

## Что НЕ доказано

1. Единицы `fv1/fv2`, включая то, где проценты, абсолютные числа, задержки или управляющие параметры.
2. Условие активации, шанс попадания, баф/дебаф, приоритеты, порядок сложения, округление, количество ударов и снижение урона целью.
3. Соответствие производному Legacy-расчёту, точному текущему Worker/D1 и числам игрового клиента.

Не меняйте боевые показатели героя или базовые D1-значения по этому отчёту. Следующий исследовательский шаг: найти независимые исходники реализации этих конкретных EP, проверить связанный триггер и только затем добавить изолированные числовые тест-векторы. Пока доказательств нет, оставлять результат `unverified`.

Объём этого исследования **не закрывает Issue #476**.
