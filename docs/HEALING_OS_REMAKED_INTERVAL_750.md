# Периодические исцеляющие умения: сверка Remaked и текущего Pandora Saga OS (0.750.0)

## Почему модель использует две секунды
1. В оригинальном [Remaked `js/calc.js`](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/bonaqu_projects/js/calc.js) расчёт `Calc('LPsec')` в исходнике явно подписан «2秒毎のLP回復量» (восстановление LP каждые 2 секунды), а `Calc('MPsec')` — «2秒毎のMP回復量» (MP каждые 2 секунды), строки около 1009–1019.
2. В актуальном снимке OS [`data/os/skills.json`](https://github.com/bonaqu/Pandora-Saga-Build-Studio/blob/bonaqu_projects/data/os/skills.json) три источника используют полные векторы `FV2=[0,0,0,2]`: 310002001 «Регенерация» (`EP_HEAL_LIFE_REGENERATOR`), 310022001 «Восстановление» (`EP_HEAL_LIFE_REGENERATOR`), 330005001 «Природное восстановление» (`EP_HEAL_MANA_REGENERATOR`).
3. Поэтому полезная расчётная подпись в Build Studio — **ОЗ/ОМ каждые 2 сек. (модель)**. Это согласованная *модель* исходников, а не доказательство того, что живой сервер никогда не менял внутренний таймер. Не смешивать величину за такт с пассивной регенерацией или постоянными ОЗ/ОМ героя.

## Источниковые расхождения, которые нельзя скрывать
- **Восстановление** (310022001): русское поле `desc` в текущем OS утверждает «24 ОЗ в течение 3 с.», тогда как вектор эффекта `FV2[3]=2`, а Remaked называет LPsec двухсекундным. Старый фанатский справочник также содержит «3秒ごと» ([таблица Стигматы](https://wikiwiki.jp/pandoras/%E3%82%B9%E3%83%86%E3%82%A3%E3%82%B0%E3%83%9E%E3%83%BC%E3%82%BF/%E3%82%B9%E3%82%AD%E3%83%AB%E3%83%86%E3%83%BC%E3%83%96%E3%83%AB)). Величина 24 не постоянна: текущая FV1 масштабируется от СД, уровня и Исцеления. UI показывает расчёт по Remaked/OS **2 сек. (модель)** и рядом предупреждает о расхождении в текстовом описании. Сначала проверять исполняемую семантику сервера, если она станет доступна; до этого не объявлять 2 или 3 секунды живым измерением.
- **Храм** (310023001→310023002): русское описание корневого умения говорит о восстановлении ОМ, но связанный `310023002` запускает `EP_HEAL_LIFE` (восстановление ОЗ). Книга героя рассчитывает ОЗ по действию, **не исправляет автоматически** оригинальное игровое описание в данных; поясняет расхождение пользователю.
- Не брать коэффициенты восстановления из старого Remaked как современные: текущие OS FV1 для Регенерации `[10,10,10,10]`, для Восстановления `[20,5,5,5]`, для Природного восстановления `[0,10,0,0]`. Порядок округления остаётся независимым по компонентам из Remaked.

## Интерфейс и формулы
- Только умения, которые доступны текущему герою по классу, уровню и освоенному зелёному мастерству, входят в «Книга героя → Эффекты умений → Лечащие умения». Не добавлять «Регенерацию» и «Восстановление» в союзные бафы.
- За одно срабатывание: `Регенерация = 10+floor(СД×0.10)+floor(уровень×0.10)+floor(Исцеление×0.10)` ОЗ; `Восстановление = 5+floor(СД×0.20)+floor(уровень×0.05)+floor(Исцеление×0.05)` ОЗ; `Природное восстановление = floor(уровень заклинателя×0.10)` ОМ.
- Для прямых лечащих умений: `floor((постоянная+ИНТ×fv1[0]/100+уровень×fv1[1]/100+Исцеление×fv1[2]/100)×множитель лечения/100)`. Ступени повышения мастерства ищутся по **следующему действительно большему целому результату** и пределу класса; расход ОМ, базовое применение и перезарядка берутся из **записи этого OS ID**.
- Время применения/перезарядка показаны **базовыми**: наложенные эффекты ускорения и серверные ограничения могут менять итоговое время. Не выдумывать точное число срабатываний за длительность навыка и суммирование «Регенерации» с «Восстановлением».
