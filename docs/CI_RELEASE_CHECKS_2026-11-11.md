# CI проверок и релизов: меньше дублей, те же критичные гарантии

Дата: 11 ноября 2026. Состояние до изменений: Node и полный Chromium запускались на PR **и повторно на push после merge**. В релизе 0.627.0 послерелизный Chromium занял примерно 125 секунд (10:03:19–10:05:24 UTC), параллельно шёл GitHub Pages и read-only контроль Worker.

## Как устроено сейчас
- На PR выполняются **все Node-регрессии** и Chromium. Сборка не сокращается за счёт удаления доказательных тестов.
- Chromium использует **quick** только для набора файлов, который можно классифицировать как текст/оформление/неизменившуюся структуру релизных метаданных. Любое изменение `pandora-studio-app.js`, игровой математики, Worker, данных каталога, билдов, аккаунтов, кода браузерных сценариев, HTML-структуры или незнакомого модуля = **full**.
- Неопределённый diff, отсутствие ожидаемого merge commit или ошибки классификатора = **full**, а не пропуск.
- Quick включает проверку авторизации/изоляции, сохранения, конфликта облака, ошибок записи, RU/EN-редакторов и адаптивности. Full добавляет остальные независимые браузерные сценарии, производительность энциклопедии и 4K/desktop/mobile скриншоты.
- Markdown-only, docs, артефакты и изменения одних Node test-файлов не запускают Chromium; Node PR-проверка остаётся доступна (для MD-only также не запускается).
- После merge GitHub Pages публикуется как раньше, а read-only production readiness проверяет версию Pages, Worker, аккаунты, D1 и 16 игровых каталогов. **Дубликат Node и Chromium на том же merge удалён.**
- Ручной `workflow_dispatch` для обоих наборов сохранён. Ручной Chromium всегда **full**. При прямых коммитах в базовую ветку (мимо PR) automatic PR CI не сработает: нормальный процесс — PR; если он обходится, требуется вручную запустить quality и Chromium. Этот компромисс осознан, не скрывать его.

## Что нельзя выключать
- Доказательные формулы, экспорт/сохранение и открытие билдов, изоляцию аккаунтов, CAS D1/Undo и актуальные RU/EN-редакторы.
- GitHub Pages deployment и **read-only** production readiness на каждый релиз.
- Авторизованная production D1 запись по Issue #203 выполняется только отдельно по разрешению владельца. Никакая ускоренная проверка не заменяет её.
- Самостоятельную остановку merge при неуспешном обязательном PR CI.

## Профиль и восстановление
Если уменьшенная выборка пропустила дефект, запустить `Chromium browser smoke` через Actions → Run workflow (full), исправить дефект и добавить соответствующий сценарий в quick либо вернуть full для нужной категории файлов. Не удалять важные тесты на основании одного успешного прогона. Перед изменениями critical UX/формул автоматически применяется full. Не делать cron и повторных postmerge UI запусков.
