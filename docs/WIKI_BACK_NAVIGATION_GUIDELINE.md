# Энциклопедия — единая кнопка возврата

## Утверждённый образец
Эталон — кнопка **«← Назад к Чести»** на страницах PvP-войн Лидия / Гихайм (релиз 0.379.0). Её расположение в левом верхнем углу карточки, до заголовка, фон, граница, радиус и размеры утверждены владельцем проекта.

Это **общий UI-компонент**, а не отдельный вариант для Honor. Все карточки предметов, предметов эффектов, локаций, монстров, NPC, сундуков, навыков, душ и подземелий используют `wikiBackButton(chapter,onBack)` из `pandora-studio-app.js`. Страница войны получает ту же фабрику через `backButton:wikiBackButton` в `PandoraHonorView.render`.

CSS кнопки живёт **только в** `pandora-studio-wiki-history.css` под селектором `.wiki-page > .wiki-return-button`. Не копировать стили в `pandora-studio-honor.css`, не возвращать правый блок `.wiki-page-nav-actions`, панель «хлебных крошек» `.wiki-page-nav` или прежнюю кнопку `.wiki-nav-button`. Новый раздел повторно использует компонент и локализованный текст.

## Контекст возврата
- При переходе по ссылке внутри энциклопедии (пользователь уже открыл список/другую карточку) кнопка вызывает браузерный `history.back()`, который восстанавливает предыдущую карточку или главу.
- При **прямом открытии карточки** без внутренней обратимой записи в истории кнопка переводит к списку текущего раздела через `openWikiChapterList()`, **не уводит на чужой сайт**.
- PvP-войны теперь используют **тот же** `wikiBackButton` и обычную историю, что предметы, локации, монстры и NPC. Специальное `onWarReturn` и состояние `psWikiHonorScroll` больше не нужны: исключения для отдельных глав запрещены.
- Кнопка всегда расположена первым элементом `.wiki-page`; иконка вещи и заголовок следуют **после** неё.
- Название пункта «Назад к …» соответствует главе RU/EN; например «Назад к Экипировке», «Назад к Локациям» / «Back to Equipment», «Back to Locations».
- Кнопка семантически `<button>`, доступна по Tab/Enter/Space, имеет видимый `:focus-visible` и не полагается на hover.

## Контроль качества
Запустить `npm test`, `npm run release:check`, `npm run test:browser`. Браузерный сценарий сравнивает геометрию и стили обычных карточек с карточкой Лидии и проверяет переход туда-обратно. В релизном UI не должно существовать второй кнопки возврата или пустой панели над заголовком.

## Асинхронная загрузка данных
Когда пользователь открывает «Честь» сразу после запуска, общий каталог D1/Wiki может ещё загружаться. `renderWiki` запускает или переиспользует `loadWiki()` и повторно отрисовывает текущую статью после успешной загрузки (только если глава всё ещё открыта). Это гарантирует появление ссылок на девять плащей и PvP-локации, не требуя повторного открытия страницы. При сбое каталога основной текст остаётся доступен.

## Точное восстановление предыдущего места (обязательно для всех глав)

При переходе из любой страницы энциклопедии в другую запись (`wikiLink` → `openWiki`) текущая запись истории обновляется через `history.replaceState` и хранит `psWikiPosition`: идентификатор главы/карточки, `#detailContent.scrollTop`, прокрутку бокового `.wiki-list`, поисковый запрос, количество показанных строк и фильтр оборудования.

Новая запись истории создаётся только после фиксации исходного состояния; ей присваивается **своё** `psWikiPosition:null`, чтобы она не наследовала чужую прокрутку. На `popstate` восстанавливаются глава, карточка и фильтры перед рендером; после обновления DOM через два `requestAnimationFrame` восстанавливаются обе позиции прокрутки. Проверять соответствие главы и карточки перед применением позиции, чтобы более поздняя навигация не получила устаревшее состояние.

Кнопка «Назад» всегда возвращает ровно **один шаг** по истории: Честь → PvP-локация → монстр → Назад возвращает к той же точке локации → Назад возвращает в то же место Чести. То же относится к плащам, PvP-войнам, сундукам, NPC и другим перекрёстным ссылкам. При прямом входе без предыдущего шага внутри энциклопедии сохраняется безопасный возврат к списку раздела.

Повторно не добавлять частных состояний вроде `psWikiHonorOrigin`, `psWikiHonorScroll` или отдельных обработчиков возврата внутри глав: все используют общий контракт. Браузерный регрессионный тест должен **нажимать видимую кнопку**, а не только `page.goBack()`, и сравнивать восстановленные `scrollTop`.
