# 0.960.0 — Реальные коэффициенты лечения из текущего OS-каталога

## Почему исправлено
В Build Studio исторические шаги вычисления исцеления Remaked уже опирались на **корректный для ноября 2026 года OS FV1**, но численные `fv1` дублировались жёсткими константами в исходнике. После обновления актуального OS JSON изменившаяся запись либо отвергалась, либо для других функций продолжала использовать прежний `FV1`. Это неправильно: действующий сервер OS — источник актуальных *величин*.

## Изменения
- `healingSpellsPreview` теперь берёт весь `FV1` **из переданного каталога умений** для обычных и улучшенных `First Aid`, `Heal`, `Healing Aura`; для `Sanctuary` отдельный коэффициент берётся из **дочернего `310023002`**, а корневой `310023001` обязан ссылаться на него точным ID (не математическая константа). `Restoration` берётся из `310022001`.
- `periodicRecoveryPreview` использует `fv1` из текущих `310002001`, `310022001`, `330005001`. `fv2` как ранее **строго** проверяет поле источника; нет догадки об истинных длительности/тиках.
- Спецификации ID, названия, классы, требования, ранг и направление применения, EP и механика подсчёта по Remaked сохранены. Защита от некорректного `fv1`: ровно четыре безопасных неотрицательных целых числа, разумные границы источника, не нулевой весь вектор. Неизвестный вектор не превращается в «подтверждённое» умение.
- Книга героя и подсказки следующего улучшения подписывают гипотетическую математическую величину как **«модель» / «model»**, а не как проверенный итоговый урон от заклинания.

## Тестовый вектор (официальный OS snapshot 26.11.2026)
`CLERIC, level 55, INT 90, SPI 70, Исцеление 60, healingPercent 120`:
`First Aid=720`, `Heal=1698`, `Healing Aura=1518`, `Sanctuary=480`, `Restoration=24`. **Все пять совпадают с прежним кодом**; речь не о подмене правильных коэффициентов. После изолированной подмены входного `fv1` для `Heal` (второе поле +10), `Sanctuary` (четвёртое поле ребёнка +7) и `Restoration` (+3) рассчитанные модели становятся `1704 / 488 / 27` соответственно. Это тест возможного будущего серверного обновления, **не реальные изменившиеся параметры игры**.

В новой регрессии — полный проход 28 профессий × уровни 1–55, действующие ID и полные исходные векторы. Формулы суммирования, округлений и тиков Remaked — **модели**, если современный OS API даёт числа, но не полный исходный код механики. Не утверждаем абсолютный PvP/PvE паритет.
