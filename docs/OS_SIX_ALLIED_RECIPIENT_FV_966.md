# 0.966.0 — Один текущий OS-источник для шести союзных усилений

Углубление задачи #476: не дублировать идентичные, но отдельно прописанные цифры в Книге героя и в модуле применения исторического Remaked. Источник чисел — **текущий официальный** `data/os/skills.json` (данные 571/571 сверены с публичным OS API). Этапы сложения, проценты и `floor` везде сохраняют статус **расчётных моделей Remaked**, а не доказанного выполнения игровым сервером.

| ID | Эффекты OS | Текущие числа |
|---|---|---|
| 320001001 — Боевой клич | TARGET `EP_DAMAGERATE_CONST`, `EP_DAMAGERATE_SCALE` | 10, 20 |
| 100055001 — Массовая сосредоточенность | TARGET `EP_TOHIT_CONST`, `EP_TOHIT_SCALE` | 20, 15 |
| 260006001 — Помощь ветра | TARGET `EP_AVOIDANCE_CONST`, `EP_AVOIDANCE_SCALE` | 15, 15 |
| 320004001 — Благословение ветра | TARGET `EP_MOVESPEED_SCALE` | 40 |
| 330004001 — Божественное благословение | TARGET `EP_MAGIC_RESISTANCE_CONST` | 25 |
| 320002001 — Благословенный покой | TARGET `EP_HEAL_TIME_SCALE` | 90 |

Теперь `PandoraOSCalculator.alliedRecipientPreviews` берёт **все шесть** из текущих `fv1[3]`, а `PandoraRemakedBuffs.applied` берет те же источники для трёх соответствующих самостоятельных выбранных эффектов. Для остальных трёх применяемые бонусы уже читались по OS в `combatSkillSource` / `supportSkillSource` — это теперь совпадает с Книгой героя при изменении коэффициента.

Поддерживается только нулевой `fv1[0..2]`, `fv2=[0,0,0,0]`, безопасные целые \(0..100\), точные `EP_*`, TARGET, ID и известная форма умения. Ввод неизвестной зависимости уровня, изменения направления или дополнительных эффектов блокирует модель. **Это не утверждение, что бонусы стакуются, или сервер использует те же стадии округления.**

Проверка `tests/os-six-allied-recipient-fv-966.test.mjs`: исходные шесть векторов, изменения всех шести констант и трёх процентных каналов, совпадение Book/применяемой логики, отрицательные изменения каждого дополнительного канала, 28 профессий × уровни 1–55, и отсутствие мутаций каталога. Обновлён тест precommit-совместимости: допустимый OS коэффициент остаётся в модели, но требует классификации совместимости; неизвестная форма по-прежнему блокирует её.

Имеющиеся сохранения и публикации D1/Worker/CAS не изменяются; CR Chromium/Node и read-only readiness обязательны. #476 остаётся OPEN.
