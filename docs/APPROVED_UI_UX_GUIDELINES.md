# Pandora Saga Build Studio — согласованные правила интерфейса

Дата: 2026-11-05. Этот документ фиксирует **уже утверждённые пользователем решения**, а не новые предложения. При доработке любого раздела сначала использовать существующие компоненты и паттерны ниже.

## 1. Источник истины и связь сущностей

- При добавлении и замене уже существующей локации, NPC, монстра, предмета, умения и другого связанного объекта **выбирать запись по имени из актуального каталога**. Выводить локализованное название, не внутренний ID.
- Действия одной связи: открыть по клику, **✎ Заменить**, **× Удалить**, **+ Добавить**. При замене сохранять место записи в списке, не создавать новую копию и не допускать повторную связь.
- Кнопка **+ Добавить** расположена сразу после последнего связанного элемента, рядом с действиями ряда, а не в отдельном бессвязном блоке.
- Поиск работает по названиям. Список ограничен, фильтруется до вывода, управляется клавиатурой. Состояния «нет совпадений», «запись уже выбрана» понятны человеку.
- Новые сущности создаются **только в профильном разделе** («Локации» для новой локации, «NPC» для нового NPC, и т. д.) с полным RU/EN редактором. Из других разделов только переход к созданию.
- Связи должны сохраняться по устойчивому внутреннему ключу. Изменение имени/перевода **не меняет ключ, URL или связь**. Читаемый текст на экране берётся у самой связанной сущности, не из второй копии.
- Если обратная запись требует **двух независимых обновлений D1**, без атомарной операции не выдавать её за одностадийную замену. Такой сценарий выделять в ROADMAP до реализации безопасной транзакции или отката.

## 2. Визуальное редактирование

- Редактор поверх страницы; вручную открытое состояние **сохраняется при переходе между разделами**. Сворачивать может только пользователь (кнопка или Escape), а не навигация.
- Кнопка в свернутом виде прилегает к **левому нижнему краю экрана**. Hover не меняет её положение, видимость и кликабельность; раскрытый переключатель находится выше шапки.
- Одна вертикальная прокрутка внутри панели редактора; нет отдельного внутреннего скролла у заголовка. Редактор не влияет на размеры рабочей области.
- Двойной клик по тексту или маленькая иконка редактирования рядом с названием, правка **на месте**, сохранение при Enter/уходе с поля. Escape отменяет. Нет дополнительных кнопок «Сохранить», если уже включено автосохранение.
- Разделы, вкладки и подзаголовки имеют две независимые подписи RU/EN в D1, но постоянные ключи. Не подставлять EN-текст в RU и не объединять оба языка на экран.
- Любое сохранение должно сохранять текущую карточку, выбранную вкладку, фильтр и прокрутку, поддерживать Undo и ошибку сохранения без потери вводимого текста.
- Центральный портрет героя — **только вход в Книгу героя**; замена расовых изображений в «Происхождение → Раса», а не на нём.

## 3. Контент и игровая точность

- В пользовательской энциклопедии не показывать внутренние ID, API, примечания о таблицах, служебные источники, устаревшие сообщения о патчах или объяснения способа расчёта.
- Не дублировать один факт в нескольких описаниях, плашках и карточках. Один смысл — одна читабельная точка входа.
- Руководство и ранги: простая формулировка условий, награды понятными словами и визуальная иерархия «звание → условие → преимущество».
- Имена игровых предметов, навыков, локаций, эффектов и профессий использовать из официального OS или подтверждённого Remaked; не заменять «похожими» иконками или самодельными переводами.
- Изменения формул, шансов выпадения, игрового каталога и прав на запись в production D1 проходят отдельную сверку. Текстовое редактирование не вправе менять расчёты.

## 4. Переиспользование и тестирование

- Вкладки: общий `PandoraWikiLabels` (текст в D1, неизменный chapter/section key).
- Списки связей: общий `wikiOwnerEntityList` с поиском, выбором и заменой по имени; специализированные списки должны стремиться к той же структуре, **не дублировать код поиска**.
- Раздел «Честь»: общий `PandoraHonorView`, отдельные основные данные в `PandoraHonorGuide`; контент редактируется без пересоздания всего интерфейса.
- Перед PR проверить Node, браузер Chromium, десктоп/узкий экран, RU/EN, клавиатуру, F5, открытие/скрытие редактора на главной, в билдах и энциклопедии, автосохранение без сброса прокрутки.
- Обновление игрового каталога — отдельный безопасный сценарий: предварительное сравнение, выбор изменений, отказ по умолчанию, никаких публикаций до явного подтверждения.
- Проверки в тестовой D1 **не являются доказательством записи в production D1**; проверять отдельно и не изменять реальные игровые данные без явного действия администратора.

## 5. Подписи выпадающих фильтров

- Название категории — пользовательская локализованная строка, а не её технический ключ. Если администратор может редактировать заголовки энциклопедии, **все подписи выпадающих фильтров также должны быть редактируемыми**.
- Нативный `<select>` использовать для выбора, а не размещать в `<option>` недоступные браузеру поля ввода. Одно компактное ✎ рядом со списком раскрывает подписи всех вариантов **в том же блоке страницы**, используя `.wiki-categories .wiki-category-line` и `.wiki-category-edit` из существующего редактора разделов, без всплывающего самодельного меню.
- Редактирование названия не переключает фильтр, не сбрасывает выбор и не меняет его ключ. RU/EN редактируются отдельно; при сохранении Enter/blur отображаемый текст обновляется сразу, при Escape изменений нет.
- Изменение структуры допустимых D1-полей требует синхронных проверок фронтенда, бизнес-валидатора и Worker. Успешная публикация GitHub Pages сама по себе **не означает**, что production Worker принимает новые поля.

- Для уже сохранённых RU-правок с отсутствующими EN-значениями допустим **сверенный пословно набор соответствий**, но не универсальный автоматический перевод неизвестного текста. Пока EN не сохранён, он может отображаться из точного безопасного соответствия; запись в D1 выполняется только после явного подтверждения администратора с предварительным просмотром. Уже сохранённые EN-тексты никогда не перезаписывать.

## 6. Открытые несогласованности

- Обратные списки спавнов из старого каталога и NPC/монстров, для которых замена меняет **две самостоятельные записи D1**, ещё требуют транзакционного заменителя или сценария с откатом. Пока используем добавление/удаление отдельно.
- Остальные отдельные редакторы связей (сундуки/обмены/подземелья) требуют постепенного перехода на общий поисковый picker без регрессий сложных шансов, цен и типов наград.
- Исходные иконки и подтверждённые RU/EN данные — отдельный источник, не объект дизайнерской импровизации.

## 7. Расовые пассивки и фильтры навыков (7 ноября 2026)

- Врождённые пассивки рас показывать в «Расовая пассивка / Racial passive». Определять состав по официальному `racialPassives` того же снимка D1, что и `skills`, **не по всем `branch:race`**, потому что туда попадают технические статусы и эффекты.
- Утверждённые названия: «Дубли навыков / Duplicate skills» и «Особое / Special». Существующие ключи `variants`, `special`, игровые ID и ссылки не менять. Название «Дубли» не означает удаления игровых версий.
- Нестандартные ручные подписи владельца имеют приоритет над новой версией заводских названий.

## 8. Быстрый поиск по двуязычным названиям (7 ноября 2026)

- При вводе каждой буквы **не создавать заново** `id=>searchTerms(type,id)` для `wikiIndex.search`. Его WeakMap-кэш полных локализованных имен должен переиспользоваться между запросами на одном снимке каталога.
- При смене источника D1 / языка RU↔EN / загруженного набора официальных английских названий переинициализировать search resolver, `nameCache` и `searchCache`, чтобы не оставалось старых названий. Не добавлять отдельный текстовый индекс на каждую кнопку/клавишу и не выключать поисковые подсказки.

## 9. Атомарная замена подтверждённой локации монстра (7 ноября 2026)

- Когда одна и та же информация хранится как обратные связи монстра ↔ локация, у базового монстра редактирование через ✎ должно обновлять готовый набор под **одним** ключом `spawnedit`, без двух последовательных запросов «удалить» и «добавить».
- Переиспользовать существующий поиск локаций; предложить для замены только подтверждённые карты игрового каталога. Виртуальные и вручную созданные ссылки остаются отдельно управляемыми, пока нет проверенной атомарной операции между разными D1 ключами.

## 10. Происхождение RU/EN (8 ноября 2026)

Утверждённые имена ВЫН/СИЛ/ПРВ/ЛВК/СД/ИНТ хранятся в одном двуязычном наборе ORIGIN_STAT_LABELS. Неизменяемые ключи старых сохранений остаются в STATS. В English интерфейсе заголовки, бюджет, итоговые подписи, aria-описания кнопок, состояния расовых пассивок и краткие подсказки навыков переводятся. Сами имена/описания игровых навыков берутся из локализованного каталога, без предположительных переводов.

## 11. Сообщения загрузки и активное сравнение (8 ноября 2026)

До загрузки приложения и при ошибке игрок видит понятное сообщение на выбранном языке, а не сырой ответ Cloudflare D1, внутренние ID, HTTP или детали реализации. Оригинальная ошибка остаётся только в консоли разработчика; игроку предлагаются штатные кнопки «Повторить загрузку» и «Открыть архивную копию». После выбора архива предупреждение о возможной неактуальности переводится при каждом переключении RU/EN. В активном управлении билдами используется единственный путь сравнения renderBuildComparison → PandoraBuildComparison.matrixRows; старый неиспользуемый compareSnapshots удалён. Регрессии обязаны проверять именно действующий путь.
