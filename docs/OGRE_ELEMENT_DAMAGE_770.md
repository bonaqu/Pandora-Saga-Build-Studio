# 0.770.0 · Публичная формула Pandora Saga OS: Ползучая ловушка → Гигантский огр

## Проверенный первичный источник

Действующий Pandora Saga OS, [встроенный оригинальный калькулятор билда](https://pandorasaga-os.com/assets/BuildCalculator-DBaXruFa.js), зафиксирован 14 ноября 2026. Его рабочие функции `Et`, `kt`, `Ie`, `ve`, `Tt`, `gt` и `xt` подтверждают **полный числовой путь удара огненным умением по монстру**. Это модель опубликованного сервером веб-калькулятора; непосредственную паритетность всех чисел с игровым клиентом ещё требуется измерить.

Реальные OS источники в репозитории: `data/os/skills.json` (три стадии умения `240005001 → 240005002 → 240005003`; завершающий `EP_ELEMENT_DAMAGE`, `powerStat=DEX`, `[680,0,350,155]`); `data/os/classes.json` (Загонщик, 41 зелёного мастерства «Ловушки», предел 90); `data/os/monsters.json` (Гигантский огр `22104`, уровень 53, 6126 ОЗ, СД 18, маг. защита 0, огонь 0, магия 17); `data/os/tables.json` (разница уровней, `magicPlus`); `itemForth.json`, вещи/души/комплекты.

## Полный алгоритм стихийного пакета

1. **Сила навыка:** `P=155+floor(DEX×680/1000)+floor(освоенные Ловушки×350/1000)`. Эффект берётся из *последнего* действия ловушки, а не из нейтрального корня.
2. **Влияние ИНТ:** `q=roundHalfToEven(INT/10)`, `base=roundHalfToEven(P×(100+q²/5+trunc(INT/5))/100)`; для огня диапазон до защиты `[base-trunc(base/10), base-trunc(base/20), base]` (при нечётном `trunc(base/10)` середина может быть дробной, поэтому вычислять как `base-trunc(base/10)/2`, не отдельно `trunc(base/20)`).
3. **Экипировка и усиления:** бонусы источников `EP_ELEMENT_DAMAGE_SCALE`, подходящих `EP_ELEMENT_DAMAGE_SCALE_FIRE`, `EP_ELEMENT_BONUS`; магическая заточка оружия **только соответствующей стихии** прибавляет `magicPlus[grade].flat` единиц элементального урона и `magicPlus[grade].ratio` к процентному усилению пакета. Это не дополнительный `MATK` на листе характеристик. Чары/песни союзника учитываются только если выбраны и посчитаны текущей моделью.
4. **Защита огра:** от огненного пакета вычитаются сопротивление огню, половина магического сопротивления `trunc(17/2)=8`, поглощение `roundHalfToEven(SPI/2)=9`, исходная маг. защита 0, поправка разницы уровней. Каждый шаг выполняет округление отдельно как в публичном ОС исходнике.
5. **Разница уровней:** при герое 45 ур. и огре 53 ур. шаг 8 `tables.lvModify` добавляет `magicProtection=4` и `mdamageRes=24%`. В моделируемом веб-калькуляторе это меняет *минимальный и средний* исход, а не уменьшает каждый максимальный удар на 24%.
6. **Результат:** для контрольной математической комбинации «Загонщик 45 ур., 70 ЛВК, 20 ИНТ, 41 зелёное Ловушки, без экипировки/дополнительных усилений» получаем **min 34 / avg 148 / max 194 ОЗ**. Это **тестовый вектор формулы**, а не данные чужого сохранённого героя. В Книге результат пересчитывается по текущему билду.
7. **Допуск:** ноль при отсутствии навыка, непроверенном векторе, недопустимой профессии/мастерстве, некорректных исходных параметрах снаряжения. Никаких рецептов и материалов из Энциклопедии в Книгу не копировать.

## Разграничение

Показывается **урон при успешном срабатывании атаки по выбранной условной цели**, а не вероятность попадания, частота активации ловушки или суммарный DPS: нужны другие правила, их не выдумываем. Никаких технических оговорок в пользовательском интерфейсе; в «Подробнее» только средний урон и влияющие показатели текущего героя. После выката исследовать расширение модели на другие умения и противников по тому же исходнику, но без безусловных общих формул для всех навыков.
