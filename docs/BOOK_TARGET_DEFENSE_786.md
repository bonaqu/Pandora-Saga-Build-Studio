# 0.786.0 · Что действительно меняет урон по выбранному монстру

## Исходные данные

- Публичный [Pandora Saga OS BuildCalculator](https://pandorasaga-os.com/assets/BuildCalculator-DBaXruFa.js): известный алгоритм одного стихийного попадания `Et → kt → Ie → ve → Tt`. Порядок округлений и коррекции уровня сохраняется дословно, без использования старой Remaked MATK.
- `data/os/skills.json`: только ранее проверенные `EP_ELEMENT_DAMAGE` и подтверждённые прямые части цепочек. `410004001` «Неотвратимый взрыв» содержит дополнительный `EP_ELEM_DELAYED_BONUS`, `330061001` «Круг света» — три `EP_ELEMENT_DAMAGE` и предшествующее изменение сопротивления. Без серверных правил порядка и задержки суммарный результат этих двух навыков **не подтверждён**.
- `data/os/monsters.json` либо тот же проверенный снимок production D1: 702 монстра, с индивидуальными уровнем, СД, магической защитой и сопротивлениями. Публичный калькулятор — математическая основа этой проекции, не измерение урона в игре.

## Почему новая часть не является догадкой

Для каждого уже вычисленного попадания выполняется тот же полный OS-расчёт ещё три раза, при прочих одинаковых условиях:

1. **Сопротивления цели:** её сопротивление выбранной стихии и половина магического сопротивления заменяются нулями только для сравнения. Пробитие от предметов, улучшение оружия, усиления союзников, прочие статусы, уровень и поглощение остаются действующими.
2. **СД и магическая защита цели:** только собственная составляющая `roundEven(SPI/2) + magicProtection` заменяется нулём. Поглощение, приходящее от разницы уровней, сохраняется.
3. **Разница уровней:** на сравнительной копии монстра уровень устанавливается равным уровню героя, остальные характеристики и сопротивления не меняются. Снова вычисляются поправки `magicAc`, `magicProtection`, `magicDamageReduction`, и весь путь попадания от начала до конца.

Книга показывает **разницу средних попаданий** между фактической целью и каждым отдельным сравнением. Положительная разница означает, что этот фактор помогает урону; отрицательная — мешает. Каждая разница получена независимо: **складывать три числа нельзя**, иначе округления и взаимодействия сопротивлений с пробитием будут учтены неверно.

Блоки UI не добавлены. На раскрытой карточке уже доступного навыка появляется компактная строка «Влияние на средний удар» только для ненулевых вкладов. Профиль сопротивлений теперь указывает **действительно выбранного монстра**, а не прежнего «Огра» при смене цели. Имя и значения берутся из текущего D1-снимка.

## Быстрый поиск 702 целей

Небольшой фильтр находится над существующим `select` внутри Книги героя; на пустом запросе остаются все 702 проверенные цели, при вводе происходит поиск по русскому и английскому названию (независимо от языка страницы) и уровню; регистр и «е/ё» не имеют значения. Текущая выбранная цель остаётся в списке, даже если не совпала с запросом. Ввод не вызывает перерасчётов и не записывается в билд/production D1; пересчёт только при выборе другой цели. Нет отдельной панели, кнопки или карточки.

## Приёмка

- `tests/os-target-defense-786.test.mjs` — контроль 34/148/194 по исходному огру, четыре принципиально разных монстра, прямой и связанный огненный/холодный/электрический/тёмный удар, СПИ и защита, изменения уровня, динамическая экипировка/мастерство, испорченные записи D1. Каждое число сравнивается с **полным повторным расчётом** при отдельно изменённом игровом источнике, а не с произвольным эталоном.
- `tests/browser-book-monsters-785.mjs` — расширенная RU/EN проверка: актуальное название и сопротивления выбранного монстра, три результата, поиск «динго», отсутствие пересчёта при наборе текста, возврат полного списка и потеря цели без подмены огром.
- Полный Node и полный Chromium до слияния; Pages, Worker и production D1 после слияния — **только чтение**.

Ограничения: настоящая серверная обработка состояний, многоударных цепочек, триггеров и задержек по игровому клиенту не измерена. В энциклопедии остаются связи действий, в Книге — только действующие проверенные числовые эффекты текущего героя.
