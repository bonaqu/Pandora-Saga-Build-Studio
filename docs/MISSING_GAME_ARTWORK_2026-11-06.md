## Дополнительная проверка влияния на сайт (6 ноября)

Цифра **260** относится к техническим записям в каталоге навыков, **а не к 260 кнопкам с пустой иконкой у игрока**. Проверили данные `classes`, `reqs`, `learnable` и связи `EP_SKILL_EXEC`:

- **45** пропущенных записей содержат хотя бы одно назначение профессии. Это не доказывает доступность в игровом дереве.
- **5** из них также имеют требования мастерства: **Автозащита** (`168051002`), **Железная чешуя** (`168052002`), **Порыв** (`260003002`), **Поглощение стихий** (`330002002`), **Освобождение** (`330003002`). Их оригиналы — приоритет после 4 предметов.
- **91** пропущенная запись вызывается другим умением через `EP_SKILL_EXEC`. Так, **Пламенная стрела** (`213608001`) запускает отдельную запись (`213608002`), а **Храм** (`310023001`) — (`310023002`). Картинки основных вызывающих умений уже архивированы. Это не доказывает идентичность изображений у вызываемого эффекта.
- **0** пропущенных записей сочетают `learnable: true` и назначенную профессию. В частности, **Помощь ветра** (`260006002`) и **Храм** (`310023002`) имеют `classes: {}`, несмотря на `learnable: true`.

Эти четыре показателя **пересекаются**: их не нужно суммировать. Команда `npm run assets:missing` теперь возвращает `skillImpact` и пояснение `skillContext` для каждого пропуска, включая связь с вызывающим навыком.

**Приоритет повторной загрузки оригиналов:** сначала 4 предмета, затем 5 навыков с требованиями мастерства и профессиями, затем другие навыки с назначенными профессиями. Команда `node scripts/mirror-os-icons.mjs --retry-404 --dry-run --limit=12` показывает начало очереди без сетевых запросов. Реальную доступность оригинальных URL надо проверять отдельно при наличии доступа к серверу OS. Здесь никакие иконки не скачаны и не заменены.
