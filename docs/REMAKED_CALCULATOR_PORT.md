# Поэтапный перенос механик Pandora Saga Simulator Remaked

**Исходные данные:** подтверждение владельца проекта от 31.10.2026, что в Simulator Remaked корректно реализованы формулы, эффекты навыков, зелий, усилений, чести, гильдий и бонусы предметов.

**Принцип:** сохраняем уже подтверждённое поведение движка Remaked и отображаем его в текущем RU/EN интерфейсе Build Studio. Не переносим исторические ID в пользовательский интерфейс, не подменяем подтверждённые текущие данные OS устаревшими и не объявляем оставшиеся механики реализованными.

## Реперные исходники

- [Remaked Legacy calc.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/js/calc.js) — расчёт всех базовых статов и модификаторов, взаимодействия навыков/чести/гильдий, восстановление, урон и сопротивления.
- [Remaked Legacy ini.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/js/ini.js) — таблицы рас, классов, навыков, чести, правил, ограничений.
- [Remaked Modern current-vitals.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/modern/current-vitals.js) — актуальные классовые коэффициенты и ОЗ/ОМ, поверх Legacy.
- [Remaked Modern skill-controls.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/modern/skill-controls.js) — современное управление навыками.
- [Текущий os-calculator.js](../os-calculator.js) — современная адаптация в Build Studio.

## Механики, подключённые к рабочему калькулятору Build Studio

| Источник | Правило Remaked | Реализация |
| --- | --- | --- |
| Раса, класс, вложенные очки | Стартовая база расы и основной профессии + вложения | `attribute-progression.js`, `os-calculator.js` |
| Вещи, души, заточка | Подтверждённые плоские бонусы, часть явных порогов улучшений | `os-calculator.js` |
| База ОЗ/ОМ | Современные классовые коэффициенты в сотых и округление вниз | `classBase()` |
| ОЗ/ОМ, +%, +N | Процент отдельно от классовой базы, затем фиксированные эффекты | `bonusFor()` |
| Гильдия: ОЗ и ОМ | Отдельные уровни, процент от классовой базы | `guildHp`, `guildMp` |
| «Знак жизни» | +250 ОЗ и +15% базы | `lifeSign` |
| Гильдия: все базовые характеристики | В Remaked `SelBuffClan_9.selectedIndex` добавляется к каждому из шести базовых статов | `attributeBuffs.guildAll` (0–6; доступные уровни проверяются Build Studio) |
| Честь «Стремление к силе» | В исполняемом `Calc('STA'..'INT')`: `Flag['Honor'] == 1` добавляет +1 **всем шести**, включая SPR; отдельная английская подсказка в `ini.js` не упоминает SPR | `attributeBuffs.honorCuriosity` |
| «Проэлиум» | `Flag['14_9']`: `floor(InBuff_1 / 10)` для STR, AGI и INT | `attributeBuffs.proelium` и `proeliumPotency` |
| Сохранения и короткие ссылки | Явно выбранные настройки, по умолчанию выключены | `fresh()`, `sanitizeSharedState()`, обновление Origin |

Для интерфейса новые бонусы находятся **внутри** свернутой вкладки «Усиления ОЗ и ОМ → Бонусы характеристик». Они не расходуют очки уровня и не меняют числа вложенных характеристик.

## Новый перенос 0.86.0 — титулы чести и зелья

- `js/ini.js Skill['Honor'][0..12]` соответствует `Flag['Honor']==1..13` в исполняемом `js/calc.js`: добавлен один **взаимоисключающий** выбор титула с названиями RU/EN и прямыми бонусами всех 13 титулов, которые можно показать во вкладке «Эффекты» без выдумывания итоговых боевых формул.
- Сохранения до 0.86 с `honorCuriosity:true` автоматически трактуются как титул 1, если новый `honorTitle` ещё не задан. При выборе другого титула бонус +1 к характеристикам исчезает. Выбор безопасно сохраняется и передаётся ссылкой.
- `js/calc.js Calc('POT')`: базовая эффективность зелий `100+floor(ВЫН²*2/1000)`. При титуле 11 («Крепкое тело») добавляется +5, `EP_MASTERY_POTION` от надетых душ добавляет указанный бонус, руна «Чо Ын» (`Flag 30_0`) +5. Для неподтверждённого профессией и навыком дополнительного процента формулы пока не вводятся.
- `modern/calculator-controls.js` (Modern 4.23): перенесён расчёт 14 исходных значений зелий, исходного fixed/percent режима и опциональной оценки с **floor** для фиксированных и **floor(maxHP*ceil(percent*potionRate)/10000)** для процентных. Только 10 вариантов с подтверждёнными предметами отображаются игроку; четыре исторические позиции нельзя подписывать выдуманными названиями.
- Подтверждённые эффекты титула показываются в карточке атрибутов с нормальными названиями; реальные атака и защита не рассчитываются через выдуманный коэффициент.
- `tests/honor-potion-parity.test.mjs`, `tests/potion-preview.test.mjs`, обновлённые тесты ссылок/усилений обеспечивают регрессии, а просмотр не включает эффект автоматически.

## Открытые работы — не выдавать за завершённые

1. Полный каталог **навыков**: привязать идентификаторы и дерево прокачки OS к флагам Remaked; разделить пассивные (автоматически действуют при выполненных условиях), включаемые активные и временные усиления с переменными уровнями.
2. **Зелья**: базовая POT, предметная Душа зелий, честь, руна и просмотр 10 текущих + 4 исторических формул перенесены. Осталось сопоставить условия профессии/навыка и независимые серверные значения для остальных специальных вариантов.
3. **Честь**: 13 титулов и прямые эффекты уже выбираются; остаётся подключить все производные боевые значения (атака, урон, сопротивления, критические параметры) к полному движку Remaked.
4. **Гильдии**: остальные ветви селекторов `SelBuffClan_*`, их диапазоны и порядок прибавок.
5. **Особые усиления**: все подтверждённые флаги `Flag['xx_y']` и входные числовые параметры `InBuff_*` с условиями класса/мастерства.
6. Полные **боевые параметры**, иммунитеты, сопротивления, скорость и восстановление, а не только HP/MP.
7. Сохранённые значения Remaked vs Build Studio: проверить матрицу классов, рас, очков, экипировки и активных флагов по эталонам клиента.
8. Визуальная проверка на GitHub Pages без GitHub Actions: мобильный дизайн, всплывающие подсказки, клавиатура, управление и прокрутка.

## Правило проверки

Для каждого перенесённого эффекта: ссылка на конкретное условие в Remaked, численный тест на включение и выключение, сочетание с экипировкой, пересчёт после изменения, сохранение/F5, короткая ссылка, и экранная проверка. Никаких автоматических правок удалённой D1 и неверифицированных замен коэффициентов.
