# Поэтапный перенос механик Pandora Saga Simulator Remaked

**Исходные данные:** подтверждение владельца проекта от 31.10.2026, что в Simulator Remaked корректно реализованы формулы, эффекты навыков, зелий, усилений, чести, гильдий и бонусы предметов.

**Принцип:** сохраняем уже подтверждённое поведение движка Remaked и отображаем его в текущем RU/EN интерфейсе Build Studio. Не переносим исторические ID в пользовательский интерфейс, не подменяем подтверждённые текущие данные OS устаревшими и не объявляем оставшиеся механики реализованными.

## Реперные исходники

- [Remaked Legacy calc.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/js/calc.js) — расчёт всех базовых статов и модификаторов, взаимодействия навыков/чести/гильдий, восстановление, урон и сопротивления.
- [Remaked Legacy ini.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/js/ini.js) — таблицы рас, классов, навыков, чести, правил, ограничений.
- [Remaked Modern current-vitals.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/modern/current-vitals.js) — актуальные классовые коэффициенты и ОЗ/ОМ, поверх Legacy.
- [Remaked Modern skill-controls.js](https://github.com/bonaqu/Pandora-Saga-Simulator-remaked/blob/main/modern/skill-controls.js) — современное управление навыками.
- [Текущий os-calculator.js](../os-calculator.js) — современная адаптация в Build Studio.

## Исправление 0.89.0 — врождённое мастерство и пороги пассивок

- `Remaked js/create.js` создаёт `Status.Skill[i]=[Skill.D[baseJob][branch], trainedExtra, Skill.P[job][branch], allocatedExtra]`. `js/calc.js` для пассивок использует **первые два зелёных** значения, а не только вручную развитые. В OS `data/os/tables.json → jobInit[baseClass].branches` исходные значения соответствуют Legacy `js/ini.js Skill.D` (воинские 5+2+5+2+4=18, ветка аколита 5+5+5=15).
- Для «Улучшения лечения» на воине с 12-го уровня мастерство ближнего боя = 18 врождённых + сумма дополнительного зелёного. Даже без вложений порог 10 уже даёт +10% эффективности зелий. Синие очки не прибавляются повторно.
- Для «Вдохновения» жреческой линии (PRIEST, CLERIC, ENCHANTER) ДУХ = 1 + floor((15 врождённых + доп. зелёные молитвы)/10). Соответствующий helper раньше занижал на один пункт при нулевой прокачке.
- Инертные классовые бонусы больше не выдаются за нулевые; сохранение/ссылки не меняют структуру. Модель врождённого мастерства подтверждена источником, но эквивалентность **всех** навыков актуальному клиенту OS по-прежнему требует проверки.

## 0.102.0 — формулы лечащих умений из исходного Remaked

- Архив `js/calc.js` после `if(Flag[5])`: `Lev=level`, `Ban=innate benevolence+trained benevolence`, `INT=итоговый интеллект`, `SPR=итоговый дух`, `LSk=процент лечения навыками`.

- Heal: обычно `floor((50+2*Lev+3*Ban+6*INT)*LSk/100)`; клирик Lv50+: `floor((105+2*Lev+5*Ban+10*INT)*LSk/100)`.
- HealingAura: обычно `floor((150+2*Lev+3*Ban+6*INT)*LSk/100)`; клирик Lv50+: `floor((150+2*Lev+4*Ban+8.5*INT)*LSk/100)`.
- Sanctuary: `floor((100+2*Lev+2*Ban+2*INT)*LSk/100)`. Restoration: `7+floor(Ban/10)+floor(SPR/5)`, без множителя LSk, исторический периодический показатель.
- Все пять чисел выводятся отдельно от зелий, с доступностью как предварительной оценкой и без притворства полной сверки с текущим OS сервером.
