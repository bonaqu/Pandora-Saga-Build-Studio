# 0.976.0 · Расовые сопротивления из актуальных Pandora Saga OS FV1

Пять расовых пассивок раньше добавляли числовые величины напрямую константами Remaked в `resistancePreview` даже при наличии актуального OS skill-каталога. Теперь **при переданном каталоге** весь набор исходных действий проверяется целиком; отдельные `FV1[3]` идут в Книгу героя и базу сопротивлений, а не в повторные константы.

| Раса | ID | EP-канал / эффект | Значение OS |
|---|---:|---|---:|
| Эльф | 900020003 | EP_CHARM_RESISTANCE_CONST / Чары | +20 |
| Человек | 900010002 | EP_IMMUNE_VIT_TYPE / физические состояния | +15 |
| Энкиду | 900050001 | EP_ONDAMAGE_FIN_DAMAGE_SCALE / получаемый физ. урон | −10 |
| Лапин | 900060001 | EP_ONDAMAGE_ELEM_SCALE / получаемый маг. урон | −10 |
| Дворф | 900030001 | EP_IMMUNE_TUMBLE / падение; EP_IMMUNE_STUN / оглушение; EP_IMMUNE_NUMB / заморозка | +10 / +10 / +10 |

У пассивки дворфа дополнительно есть `EP_RACE_TOUGH_HEART FV1[3]=20`: он **проверяется как четвёртая исходная операция**, но *не* складывается с сопротивлениями. Для пяти пассивок модель отклоняет новые EP, CASTER вместо TARGET, чужие классы, изменения branchRaw/requirements и неизвестные FV2. Поддерживаемые OS-изменения FV1[3] считываются по отдельности. `racialStatusSourcePreview` доступен для воспроизводимой диагностики.

Совместимость: старые вызовы калькулятора, не передающие `skillCatalog`, сохраняют исторические Remaked значения **только как legacy-model fallback**. Живой Build Studio передаёт `combatContext.skillCatalog` из авторитетного OS/D1 — если соответствующий источник пропал/изменился неизвестно, бонус не придумывается. API-числа подтверждены, механизм их применения сервером и порядок округления по-прежнему `modelOnly`.

Регрессии: `tests/os-racial-resistances-fv-976.test.mjs`: 5 рас, все 28 классов, независимые изменения FV1, недопустимые каналы и исходная неизменность. Никаких записей D1, Worker/CAS, игровых данных или сохранённых билдов. Issue #476 остаётся открытой.
