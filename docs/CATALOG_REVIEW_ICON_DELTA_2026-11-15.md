# Изображения актуального D1: аудит новых оригиналов

Снимок: `ps-ca9a604163b54a2da5c83ea55077ef96`, 15 ноября 2026.

При сравнении **замороженного D1-кандидата** с историческим `data/os` предварительно обнаружено **20 новых уникальных путей оригинальных иконок**: **19 предметных** и **1 умения** (внутреннее действие «Песчаная буря», ID `420007102`). В `assets/os-icon-manifest.json` для них нет подтверждённых локальных WebP. Новые значки душ используют ранее известные пути; самостоятельных новых идентификаторов иконок душ нет.

**Это не означает, что 20 изображений не существует в игре или возвращают HTTP 404.** Они ещё не проверены/не перенесены в локальный архив. Для отображения нельзя подставлять случайную картинку по похожему названию или объявлять новые пути «потерянными» только из-за отсутствия в старом manifest.

Команда `node scripts/audit-catalog-review-icon-delta.mjs` показывает точный список новых стемов, привязанных предметов/умений и статусы `verified`/`unverified` на основе наличия записи в manifest **и фактического WebP-файла**. `--strict` блокирует релиз при оставшихся непроверенных новых путях, обычная команда возвращает отчёт. Действие read-only: не обращается к сети, не изменяет D1, `data/os`, manifest и ассеты.

В отличие от существующего аудита старого комплекта картинок, новый отчёт учитывает 17-файловый кандидат и безопасно прекращает показывать новые отличия после будущей замены архива. Его можно использовать при принятии #602 и отдельно собирать подтверждённые оригиналы в последующем PR.

Проверка: `node --test tests/catalog-review-icon-delta-20261115.test.mjs`; затем обязательные Node + Chromium.

## Разделение состояния оригиналов в ревизии резервного каталога

По проверенному локальному манифесту: 1 454 оригинальных путей для нового D1; из них 1 170 имеют действительные локальные WebP, 264 имеют **ранее зафиксированный HTTP 404**, ещё **20 новых путей не были проверены по сети** (`Not attempted`). Три исторических оригинала `I_018008_00`, `I_018009_00`, `I_018011_00` остались на диске, но больше не ссылаются на текущий источник. Их нельзя использовать для подмены новых вещей.

`npm run assets:audit` должен сверять каждый статус с файлом на диске, разрешая отсутствие картинки **только при явной записи** о подтверждённом 404 или ещё не проверенном URL. `npm run assets:audit:strict` остаётся красным, пока настоящих оригиналов нет. Команда восстановления изображений может запланировать 20 ещё не проверенных URL, не выдавая их за старые 404 и не генерируя похожие картинки. Пользовательский UI не получает вымышленных изображений.

Эти изменения остаются в диагностическом draft PR #611 до полного принятия других регрессий и данных. Релиз рабочего архива требует отдельного разрешения; production D1 не записывается.
