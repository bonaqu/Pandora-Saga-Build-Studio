# Публичный онлайн-режим: Cloudflare D1 и сохранность билда

## Правило

Публичный Pandora Saga Build Studio открывает редактор только после успешной загрузки **согласованного снимка D1** и редакторских переопределений. Кнопка «Открыть архивную копию» отсутствует. Встроенные `data/os/` доступны только на `localhost` / `127.0.0.1` для разработки и независимого Chromium CI — не как запасной источник игрового каталога на опубликованном сайте.

`navigator.onLine` — вспомогательный сигнал, а не доказательство актуальности. Первичное подтверждение выполняется текущим строгим загрузчиком: девять каталогов с одинаковым `x-ps-catalog-snapshot`, заголовком `x-ps-catalog: d1`, проверками неполноты/структуры и обязательным чтением `/api/overrides`.

## Если первый запуск не удался

Экран остаётся поверх редактора и показывает только **«Повторить подключение»**. Ошибка не предлагает использовать устаревший каталог и не выдаёт подробности Worker/D1/API. При доступном соединении выполняются автоматические попытки с ограниченной частотой до успешной полной проверки. Вручную повторить попытку можно раньше.

## Во время открытого билда

Каждые 45 секунд при видимой странице, при возвращении фокуса и по событию возврата соединения проверяются **только чтением**:

1. `GET /api/catalog/meta.json` — успешный ответ, `x-ps-catalog: d1`, идентификатор снимка и обязательные счётчики.
2. `GET /api/overrides` — успешный ответ и объект авторских переопределений RU/EN.

Эти данные сопоставляются со снимком, первоначально принятым редактором. При сетевой ошибке интерфейс блокирует дальнейшее редактирование с прежними данными, **но не очищает** черновик, библиотеку, вкладки, авторизацию или формы. Перед блокировкой выполняется попытка сохранить владельческий текущий черновик и локальную библиотеку. Если локальное хранилище заполнено, сообщение прямо запрещает закрывать вкладку: сохранение не заявляется как успешное.

**Тот же снимок после восстановления:** блокирующий экран закрывается, открытый герой остаётся на месте; только после повторной проверки запускается существующая облачная синхронизация по учётной записи. Несохранённый текущий герой не отправляется в D1 автоматически. Если локальная запись не удалась, редактор продолжает показывать блокирующее предупреждение «Не удалось сохранить изменения» и кнопку «Повторить сохранение» даже после восстановления сети, пока повторная запись в браузер не станет успешной.

**Новый снимок или изменённые авторские тексты:** редактор остаётся заблокированным до явного «Сохранить и перезагрузить». Если у авторизованного редактора ещё открыт несохранённый текст, экран предлагает выделить и скопировать его, а затем отдельно подтвердить перезагрузку: автоматической D1-записи по потере фокуса не происходит. Рефреш сначала выполняет `pandora:before-update`, проверяет сохранность черновика и библиотеки и защищает незавершённые операции аккаунта/CAS. Старые игровые данные не подменяются посреди расчёта. Повторная загрузка снова требует всей строгой проверки D1. Обычное обновление версий UI продолжает обслуживать `pandora-studio-update-manager.js`.

Простой доступ к интернету не доказывает, что текущий D1 отражает последние правки **игрового сервера Pandora Saga OS**. Актуализация данных игры — отдельный процесс «Обновление игрового каталога».

## Проверка во время первоначальной загрузки

Каталог на публичном сайте загружается и проходит структурную проверку, но до заключительной сверки D1 и редакторских текстов нормализация старых очков навыков, экипировки и душ выполняется только **в памяти**. Если загрузка отклонена, исходный черновик восстанавливается; запись в браузер происходит только после подтверждения онлайн-снимка. Ручные повторы и автоматические попытки не запускаются параллельно, чтобы не смешать два набора данных.

## Защитные условия

- Не удалять сохранённые билды при неуспешном сетевом запросе.
- Не подменять ошибку облачной записи сообщением «сохранено».
- Не переходить к локальному архиву на публичном сайте.
- Не регистрировать Service Worker или тайный офлайн-кэш каталога.
- Не обновлять экран через перезагрузку в фоне и не стирать одноразовый код восстановления.
- Не писать в production D1 в проверках: тестовый API имитируется локальными ответами.
- Не разрешать отправку форм, клавиатурные действия и случайное сохранение owner-редактора по `blur` за блокирующим экраном.
- Не запускать загрузку облачной библиотеки аккаунта до подтверждения D1, а после восстановленного соединения сразу повторять чтение библиотеки без дополнительного PUT.

## Проверка изменений

`npm test`, `npm run test:browser`, `npm run release:check`. Браузерные сценарии `online-d1-required-878` и `online-owner-draft-879` проверяют первоначальную недоступность, ручное подключение, сохранение героя, отказ при неуспешном повторе, восстановление той же версии, запрет незаметной подмены, явную перезагрузку на следующей версии и отсутствие записей в D1.

Владельцу не нужны эксперименты в реальном клиенте Pandora Saga. GitHub Actions проверяет код, а опубликованную Pages/Worker-D1-связку следует отдельно подтверждать на чтение после выкладки.

Аудит корректности online-only режима проводится в [Issue #723](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/723); прежнее прохождение CI само по себе не заменяет проверки ситуаций, ранее не покрытых тестами.
