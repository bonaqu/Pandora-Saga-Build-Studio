# Read-only D1 ↔ GitHub snapshot parity — 2026-11-08

Проведена прямая проверка публичных данных GitHub Pages и действующего Worker/D1 (HTTP 200). Это **не** проверка авторизованной записи, миграции или реального игрового клиента.

**Полностью совпали:** 1 116 предметов, 702 монстра, 569 навыков, 112 душ, 187 таблиц добычи монстров, 236 NPC-обменов, 32 сундука, 14 карт, 6 расовых реестров пассивок, 28 классов, 162 набора itemForth, 3 набора unison, справочник expertise, английский словарь stringsEn и вся структура общих игровых таблиц. Порядок полей JSON нормализован при сравнении; полные записи, включая имена, эффекты и связи, сравнивались без частичного семплирования.

**Единственная найденная разница среди 16 игровых ресурсов:** в D1 у шести записей `instances` отсутствует `blurbRu`, присутствующий в GitHub snapshot. Все остальные поля этих записей совпадают. В текущем клиенте уже предусмотрена безопасная подстановка локального `blurbRu`, только если оригинальный `blurb` полностью совпадает; это **не означает**, что D1 уже содержит переводы.

**Действие в production:** пока не вносилось. Для полного перехода D1 в источник RU/EN необходимо принять 6 описаний в проверенную новую версию игрового каталога штатным staged publish, с контролем связей и rollback. Не выполнять неподтверждённые UPDATE существующего активного snapshot.

**Повторяемая проверка:** `npm run catalog:parity:live` сравнивает все 16 JSON с активным D1 snapshot. `npm run catalog:parity:live -- --strict-ru` дополнительно считается ошибкой, пока русские описания отсутствуют в базе. Запросы только GET без токенов и D1-записей.

Служебные `legacyLocale` и `tradeMeta` не имеют самостоятельного одноимённого JSON в архиве; последний включён в общий ресурс `trades`, который сверяется полностью. Метаданные `meta` специально исключены из строгого сравнения: D1-представление содержит curated-сведения, а локальная копия — источник `sha`; одинаковая структура этих двух документов не гарантируется. Рабочие метаданные проверяются отдельной командой `npm run connection:check:full`.

Ресурсы: [D1 meta](https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/meta.json), [Pages meta](https://bonaqu.github.io/Pandora-Saga-Build-Studio/data/os/meta.json), [D1 instances](https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/instances.json), [Pages instances](https://bonaqu.github.io/Pandora-Saga-Build-Studio/data/os/instances.json).

Отчёт не считает расхождения допустимыми и оставляет CI красным до обоснованного исправления публикации или источника данных.

## Прямая повторная сверка опубликованных JSON, 2026-11-08

Прямые GET к Pages и D1 с одинаковым заголовком D1 snapshot `ps-448434407e394325a432b8345206b922` подтвердили равное количество ID для предметов (1116), душ (112) и словарных разделов. Однако строгая проверка **правильно** замечает различия оформления: 834 русских `items.desc` и 13 `souls.desc`, а также 833 английских описания предметов и 20 душ. Подавляющая часть вызвана восстановленными `<br>` в D1, отсутствующими в архивном тексте; эти переносы важны и не должны удаляться из D1 ради зелёного CI.

Из 834 RU описаний предметов 831 совпадает после удаления только разметки переноса и пробельных различий. Три особых случая — `13083` (выделение в описании), `51060` (ссылка на тыкву) и `80100` (ссылка на билет испытаний). Для двух последних в 0.499.0 исходный архив дополнен **точным текстом опубликованного D1**, включая ссылку и игровые переносы; ни одна запись D1 не менялась. `13083` оставлен для отдельного рецензирования богатого текста, без автоматической правки.

Команда аудита теперь сопровождает FAIL раздельными количествами различий переносов, inline-разметки, ссылок на предметы и прочего текста без утечки названий и ID в CI. **Сравнение остаётся строгим**: новая неизвестная правка или лишняя разметка не может стать успешной проверкой. Публичные источники: [архив items](https://bonaqu.github.io/Pandora-Saga-Build-Studio/data/os/items.json), [D1 items](https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/items.json), [D1 stringsEn](https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/stringsEn.json).

## Проверка целостности ссылок (0.500.0)

Сквозной read-only аудит дополнительно проверяет `<item N>` в описаниях предметов и душ RU/EN по одному каталогу ID: отдельно в GitHub-архиве и D1 snapshot. Даже если обе стороны содержат одну и ту же сломанную ссылку и строгий diff считает JSON равным, отсутствующий целевой предмет теперь отмечается ошибкой. В CI выводится только число ссылок и неразрешённых целей (без имён, текстов и ID). Попутно исправлена некорректная формулировка сводки: раньше при трёх расхождениях в 16 **прочитанных** ресурсах печаталось «13 из 16 checked», теперь число прочитанных ресурсов не уменьшается от количества ошибок.

Добавлен push-триггер по bonaqu_projects с ожиданием соответствующей публичной site-version (до 60 проверок через 5 с), единая отменяющая конкуренция для новых релизов. Условия по Worker/D1 остаются read-only, доступ к секретам не требуется. Сохранены workflow_run, schedule и ручной запуск. Требуется проверить **реальный run после merge**: статические тесты не доказывают, что GitHub сгенерировал событие.

## Подтверждение актуального источника двух боссов (0.502.0)

После того как мониторинг 0.501.0 [run #42503012161](https://github.com/bonaqu/Pandora-Saga-Build-Studio/actions/runs/42503012161) обнаружил две разницы `monsters.life`, **8 ноября 2026 года** выполнено независимое GET-сравнение:

- [Текущая официальная игровая таблица Pandora Saga OS](https://pandorasaga-os.com/gamedata/monsters.json): 702 записи.
- [Активный D1-каталог](https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/monsters.json): 702 записи, **все записи полностью совпадают с официальной игровой таблицей**, включая вложенные сопротивления.
- [Предыдущий резервный архив GitHub](https://bonaqu.github.io/Pandora-Saga-Build-Studio/data/os/monsters.json): 702 записи, **две неверные величины life**: ID 43650 (5 000 000 вместо 1 250 000), ID 43732 (1 600 000 вместо 1 350 000).

Первичный источник [meta.json Pandora Saga OS](https://pandorasaga-os.com/gamedata/meta.json) содержит SHA игрового файла `monster/monster.csv = f637f83a84a49c74`, тогда как старый архив хранил `b99edf06cb49f754`. В релизе 0.502.0 только эти **две величины** в резервном `data/os/monsters.json` и **один** исходный SHA в `data/os/meta.json` синхронизированы с текущим официальным OS. Остальные отличающиеся source SHA (`shared/base.json`, `event/*.csv`) без проверки влияющих данных **не менялись**. D1 вообще не записывался, клиентские формулы не тронуты.

Условие production-приёмки: после Pages 0.502.0 read-only `catalog:parity:live` должен показать `monsters: 702 source records match D1`. Оставшиеся текстовые различия предметов, душ и EN остаются отдельной задачей #284 и не маскируются.

## Восстановление оригинальных описаний из текущей игры (0.503.0)

Независимая прямая сверка 8 ноября 2026 года: полные JSON-каталоги текущего Pandora Saga OS (https://pandorasaga-os.com/gamedata/) и рабочего D1 (https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/) целиком совпадают для всех 1116 предметов, 112 душ и всех 11 верхнеуровневых разделов английского словаря. В архивном fallback оставались исключительно расхождения в полях описаний: 832 RU items.desc, 13 RU souls.desc, 833 EN stringsEn.items.d, 20 EN stringsEn.souls.d.

В 0.503.0 **только эти четыре набора полей** восстановлены точными строками текущей официальной игры. Перед созданием патча автоматически требовалось полное совпадение game API с D1 и отсутствие каких-либо отличий в остальных полях. Сохранены исходные переносы <br>, выделение <b>, ссылки на предметы и многострочные эффекты. Ни один ID, игровой параметр, название, торговая связь, навык, таблица заточки или Worker/D1 не изменялись.

Принятие изменения подтверждается отдельными Node/Chromium тестами и реальным read-only post-deploy parity. Известные шесть отсутствующих RU blurbRu в D1 остаются предупреждением, а не молча переписываются.

## Удаление устаревшей клиентской подмены монстров (0.504.0)

После подтверждения всех 702 монстров в текущем игровом источнике и D1, удалён исторический read-only overlay из загрузчика Энциклопедии. Он имел жёстко зашитые старые source SHA и мог исправлять ОЗ Восставшего короля на уже опровергнутые 5 млн при работе со старым D1. Теперь даже устаревший валидный D1 snapshot **не подменяется архивом скрытно**; если D1 недоступен или не проходит проверку связей, сохраняется прежняя атомарная fallback-политика. Проверенное RU-переводное дополнение только при полном совпадении исходного английского описания подземелья сохранено. Нет D1-записей и изменений игровых формул.

## Проверка внешнего игрового источника из Worker (0.505.0)

Ранее readiness подтверждал только существование capability /api/source-health. Теперь диагностический скрипт делает отдельный анонимный GET и различает доступный внешний игровой JSON и временную сетевую ошибку. Это WARN, а не блокирующая ошибка каталога D1: текущие игроки продолжают пользоваться опубликованным D1, даже если админская проверка новых данных сейчас не может обратиться к игровому сайту. Скрипт не отправляет токены и не публикует содержимое ответа в логи.
