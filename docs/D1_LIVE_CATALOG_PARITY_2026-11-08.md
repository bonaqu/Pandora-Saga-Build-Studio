# Read-only D1 ↔ GitHub snapshot parity — 2026-11-08

Проведена прямая проверка публичных данных GitHub Pages и действующего Worker/D1 (HTTP 200). Это **не** проверка авторизованной записи, миграции или реального игрового клиента.

**Полностью совпали:** 1 116 предметов, 702 монстра, 569 навыков, 112 душ, 187 таблиц добычи монстров, 236 NPC-обменов, 32 сундука, 14 карт, 6 расовых реестров пассивок, 28 классов, 162 набора itemForth, 3 набора unison, справочник expertise, английский словарь stringsEn и вся структура общих игровых таблиц. Порядок полей JSON нормализован при сравнении; полные записи, включая имена, эффекты и связи, сравнивались без частичного семплирования.

**Единственная найденная разница среди 16 игровых ресурсов:** в D1 у шести записей `instances` отсутствует `blurbRu`, присутствующий в GitHub snapshot. Все остальные поля этих записей совпадают. В текущем клиенте уже предусмотрена безопасная подстановка локального `blurbRu`, только если оригинальный `blurb` полностью совпадает; это **не означает**, что D1 уже содержит переводы.

**Действие в production:** пока не вносилось. Для полного перехода D1 в источник RU/EN необходимо принять 6 описаний в проверенную новую версию игрового каталога штатным staged publish, с контролем связей и rollback. Не выполнять неподтверждённые UPDATE существующего активного snapshot.

**Повторяемая проверка:** `npm run catalog:parity:live` сравнивает все 16 JSON с активным D1 snapshot. `npm run catalog:parity:live -- --strict-ru` дополнительно считается ошибкой, пока русские описания отсутствуют в базе. Запросы только GET без токенов и D1-записей.

Служебные `legacyLocale` и `tradeMeta` не имеют самостоятельного одноимённого JSON в архиве; последний включён в общий ресурс `trades`, который сверяется полностью. Метаданные `meta` специально исключены из строгого сравнения: D1-представление содержит curated-сведения, а локальная копия — источник `sha`; одинаковая структура этих двух документов не гарантируется. Рабочие метаданные проверяются отдельной командой `npm run connection:check:full`.

Ресурсы: [D1 meta](https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/meta.json), [Pages meta](https://bonaqu.github.io/Pandora-Saga-Build-Studio/data/os/meta.json), [D1 instances](https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/instances.json), [Pages instances](https://bonaqu.github.io/Pandora-Saga-Build-Studio/data/os/instances.json).

## Автоматическая проверка (0.492.0)

В `.github/workflows/live-readonly.yml` добавлен шаг `npm run catalog:parity:live`. Триггеры уже существующего workflow: успешное завершение GitHub Pages deployment, ежедневная проверка и ручной запуск. Перед аудитом ждём опубликованную версию и проверяем `/api/health`, CORS и готовность публичного каталога. Никакие токены или действия записи не нужны. Режим `--strict-ru` остаётся ручным до штатного исправления описаний в D1.

Автоматический допуск ограничен точным списком шести проверенных ID (20030040, 20030070, 20030080, 20030090, 20030100, 20030110): отсутствие нового русского перевода вне этого списка — ошибка, а не ещё одно предупреждение.

## Повторный автоматический аудит 0.492.0 · выявлен дрейф

Проверка [run #42475378896](https://github.com/bonaqu/Pandora-Saga-Build-Studio/actions/runs/42475378896), выполненная для опубликованного 0.492.0, прошла readiness (Pages, Worker, D1 и CORS), но провалила полную сверку **items, souls, stringsEn**. Прочие 13 ресурсов прошли с уже известным предупреждением о шести отсутствующих `blurbRu`. Старый успешный отчёт выше отражает более ранний снимок и **не является доказательством совпадения на 0.492.0 или позже**.

В релизе 0.496.0 скрипт при повторении расхождения выводит только количество отсутствующих, дополнительных и отличающихся записей плюс названия полей схемы. **Значения, имена, ID и секреты не выводятся, D1 не изменяется**. Отчёт не считает расхождения допустимыми и оставляет CI красным до обоснованного исправления публикации или источника данных.
