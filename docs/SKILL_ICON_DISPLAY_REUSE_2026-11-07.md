# Игровые иконки навыков: отображение и происхождение

Дата: 7 ноября 2026 г. · Авторизованное пользователем переиспользование существующих картинок

## Исходные факты

По отчёту локального исследования клиента Pandora Saga OS от 6 ноября 2026 года Codex нашёл в декодированных индексах **7 288 DDS/TGA** и подтверждённые одноимённые ресурсы для всех **1 173** файлов текущего зеркала. При этом **ни одного точного оригинального имени для 264 недостающих файлов в индексах текущего клиента не обнаружено**. Локальная исследовательская папка `D:\CODEX\Tasks\Pandora-Saga-Artwork-Research` и её исходные инструменты **не были опубликованы** в GitHub. Не следует выдавать её содержимое за автоматически доступное на GitHub.

## Что меняется в интерфейсе

Пользователь одобрил отображение **уже существующей** игровой иконки для навыков с одинаковыми русскими именами. Для перечисленных им семейств ранги I, II, III и далее используют изображение из доступного ранга той же семьи. Это решение об **оформлении**, а не о тождестве внутренних графических файлов игры.

Приоритет отображения на всех экранах Build Studio:

1. Иконка, которую владелец явно установил для конкретного навыка.
2. Подтверждённый локальный оригинал **того же ID**.
3. Переиспользование оригинала по `displayAliases.skills` для утверждённого имени или семейства рангов.
4. Для новых D1-записей, отсутствующих в сохранённом каталоге, — поиск локального оригинала по **точно совпадающему отображаемому названию** с кэшированием.
5. Иначе — оригинальная иконка клиента с вопросительным знаком `assets/skills/icons/skill_unknown.webp`.

Непривязанные к записи навыка заголовки/ветки по-прежнему используют соответствующую иконку ветки, когда она есть. Неподтверждённые URL `pandorasaga-os.com` в браузере не запрашиваются повторно.

## Покрытие сохранённого каталога

| Источник значка в интерфейсе | Записей |
|---|---:|
| Существующий оригинал по ID | 286 |
| Переиспользование по **точному названию** | 130 |
| Переиспользование по утверждённому **семейству рангов** | 71 |
| Нет подходящего оригинала: игровой значок «?» | 59 |
| **Всего записей навыков с заданной иконкой ID** | **546** |

Число 546 — уникальные адресуемые ресурсы навыков текущего манифеста; количество записей объектов `skills.json` может отличаться. **264 отсутствующих оригинала и 1 173 подтверждённых локальных оригинала не изменены.** Новая иконка «?» и ссылки на уже существующие изображения не считаются восстановленными оригиналами.

Примеры: Катапульта, Таран, Контратака, Помощь ветра, Пружинная ловушка, Огненный взрыв; семейства Магистр чести / исцеления / битвы / магии, Сила / Дух / Мощь / Честь / Опыт гильдии, Восстановление силы / духа, Физическая / Магическая устойчивость.

Название «Барьер» не обнаружено в сохранённом `data/os/skills.json` на момент этой ревизии. Если оно имеется в загружаемом D1-каталоге, сайт попробует найти **точное совпадение названия** среди навыков с локальным оригиналом. Без такого совпадения останется «?»; не нужно подставлять случайное изображение.

## Новый значок неизвестного навыка

Исходник — предоставленная пользователем картинка **64 × 64 RGB** из игрового клиента Pandora Saga OS. Сохранены исходные пиксели и сама тёмная плитка с вопросительным знаком; только внешнее чёрное поле сделано прозрачным, выполнено аккуратное кадрирование до **39 × 37** и lossless WebP. Новая иконка хранится отдельно от `os-icon-manifest.json.icons.skills`.

## Воспроизводимость и контроль

- `node scripts/skill-icon-display-aliases.mjs` проверяет актуальность производных привязок (без записи).
- `node scripts/skill-icon-display-aliases.mjs --write` воспроизводимо пересоздаёт `displayAliases.skills` после изменения исходного каталога.
- `node scripts/mirror-os-icons.mjs` обновляет алиасы после импорта новых оригиналов.
- `npm run assets:audit` проверяет наличие настоящих файлов, отсутствие подмены и корректность привязок.
- Node и Chromium тестируют приоритеты, доступность изображений и отсутствие ошибок.

Важно: использовать **одну физическую копию** каждого уже существующего игрового изображения и отображать её несколькими ID. Не создавать сотни файлов-копий под недостающие ID, иначе станет невозможно отличить настоящие ресурсы от заимствованных визуальных замен.
