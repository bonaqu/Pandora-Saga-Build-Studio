# Pandora Saga OS → Build Studio: официальная проверка значений (26.11.2026)

**Источник:** непосредственно публичные JSON действующего сервера, `https://pandorasaga-os.com/gamedata/<name>.json`; запасной хост `www.pandorasaga-os.com`. Документация игрового сайта [говорит](https://pandorasaga-os.com/), что Wiki/калькулятор основаны на файлах игры.

## Прямой снимок 26 ноября (не D1, не выдуманные цифры)

Проверены свежие `skills`, `classes`, `expertise`, `items`, `souls`, `monsters`, `drops`, `maps`, `instances`. Структурированная сверка каждого поля:

- `skills`: **571/571** полностью одинаковы; `classes`: **28/28**, `expertise`: **4/4**.
- `monsters`: **708/708**, `drops`: **180/180**, `maps`: **14/14**.
- `items`: **1140/1140** одинаковые поля **кроме** `desc` у 858 ID: Build Studio сохраняет HTML-переносы `<br>`, официальный JSON отдаёт тот же текст слитно. **Числовых отличий не выявлено**.
- `souls`: **115/115** одинаковые поля **кроме** `desc` у 15 ID: только HTML-переносы.
- `instances`: **6/6** одинаковые официальные поля, в локальной версии к ним добавлены шесть `blurbRu`; это самостоятельные переводы, не серверные значения.
- `meta.json` сервера включает `sha` с указателями на реальные game-файлы. В локальной `meta.json` вместо них хранится `curated`. Эти поля не равны по смыслу: `sha` — происхождение файла OS; `curated` — редакторский слой Build Studio, его нельзя подставлять в игровую механику.

Проверенный SHA из **живого официального meta**: `skill/skill.csv = 5470e489b52a24aa`. Именно этому снимку соответствует локальный `data/os/skills.json` (571 ID). Это доказательство совпадения **опубликованных значений**, а не серверного порядка округления/проков.

## Постоянная повторяемая проверка

```bash
node scripts/audit-official-os-source.mjs
node scripts/audit-official-os-source.mjs --all
node --test tests/os-live-official-source-parity-476.test.mjs
```

Команда делает **только фиксированные GET** с двух доменов, перечень наборов заранее задан. Никаких токенов, записей D1, публикаций или правок кода. Сравнение строгое по всем значениям JSON; **исключения строго ограничены** форматирующими `<br>` в текстах предметов/душ, русскими `blurbRu` подземелий и собственными `curated` данными `meta`. Техническая недоступность upstream не выдаётся за числовое изменение и наоборот. При несоответствии/недоступности утилита завершает выполнение с ошибкой и показывает имена расхождений, **не публикуя непроверенные изменения**.

**Граница доказательства:** API подтверждает значения `fv1/fv2`, базовые HP/MP, классы, требования, предметы, души и т. п.; но доступный набор JSON не содержит исходный C++/серверный код вычисления урона. Поэтому Remaked 2E используется для стадии вычислений только как независимый алгоритмический источник-кандидат; формула/округление без игровой верификации остаются `modeled`, а не `verified`.

Следующий этап #476: использовать регистр исходных форм `EP_*` и точные OS параметры для расширения числовых моделей, не применяя их к сохранённым билдам до подтверждения.

## Дополнительная проверка в релизном CI (0.961.0)

После защищённого объединения GitHub Actions отдельно сверяет **17 оригинальных файлов OS** с исходным каталогом GitHub командой `node scripts/audit-official-os-source.mjs --observe`. Она использует готовую модель [PR #831](https://github.com/bonaqu/Pandora-Saga-Build-Studio/pull/831), включая допустимые отличия оформленных переносов, локализованных описаний подземелий и служебных метаданных. GitHub Step Summary показывает совпадения и отклонения; *недоступность сайта OS не блокирует* публикацию уже протестированного интерфейса и не меняет D1.

`npm run os:source:live` по-прежнему строгая отдельная проверка, завершается с ошибкой при расхождении. Текущий `tables.levelCap` — **50**, по прямому свежему API 26.11.2026; планировщик Build Studio — **до 55**, это отдельное решение проекта. Ни подтверждённая таблица, ни алгоритм Remaked сами по себе не доказывают неизвестный серверный порядок округлений.
