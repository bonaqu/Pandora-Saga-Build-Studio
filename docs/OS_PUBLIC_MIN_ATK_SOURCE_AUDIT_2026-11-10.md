## Аудит 0.598.0 — отмена специальных min–max в пользу общей формулы

По замечанию владельца пользовательский runtime не должен подставлять min–max только для конкретного билда. В релизе 0.598.0 удалены все наблюдавшиеся индивидуальные таблицы минимума из `pandora-os-character-calculator.js`. Проверенные 189–219/229–266, 9–12 и 50–74 **сохранены как независимые экспериментальные эталоны**, а в Книге героя пока показывается вычисленный универсально максимум АТК без непроверенной нижней границы.

Впервые удалось прочитать публичный JS актуального калькулятора OS:
https://pandorasaga-os.com/assets/BuildCalculator-DgAOFedT.js

В функции `xa(abilities, level, weapon, profic, tables.weaponPlus, modifiers)`:
- `damage_rate` = физическая атака по опубликованной формуле силы, + заточка, + источниковые плоские и % бонусы;
- `damage_potential` = `roundHalfEven(effectivePEN / (200 + 6*weaponProficiency) * 100)`, где `effectivePEN` включает `weapon.PEN` и эффекты пробивания;
- `damage_min` = `damage_rate - floor(damage_potential * damage_rate / 100)`;
- `damage_max` = `damage_rate`.
Карта оружия→ветка: `1H_SWORD,2H_SWORD,1H_TRUMP_WEAPON -> slash`; `1H_AXE,2H_AXE -> brush`; `1H_BLUNT_WEAPON,2H_BLUNT_WEAPON,WAND,STAFF -> blow`; `POLE_ARM,LANCE -> thrust`; `BOW,CROSSBOW -> archery`; `2H_TRUMP_WEAPON -> assassin`; `BARE_HAND,MARTIAL_WEAPON -> martial`.

Сравнение с **окном персонажа реальной игры** не совпало без дополнительных объяснений:
- Heavy Crossbow ID2411: `PEN=90`, предполагаемое `archery=5`, `damage_max=74`. Публичная `xa` даёт `roundHalfEven(90/(200+6*5)*100)=39` и `74-floor(74*.39)=46`, клиент показывает **50–74**.
- Zephyr Spear ID1483: `PEN=80`, по уточнённому скриншоту Колющий показывает **56.0(56)/90**: зелёное 56, потенциал 56, предел 90. При `thrust=56`, `damage_max=219` текущая `xa` даёт `roundHalfEven(80/(200+6*56)*100)=15`, `219-floor(219*.15)=187`, тогда как игровой клиент показывает **189–219**. С кличем она даёт 227–266 вместо 229–266. Это оставляет открытым вопрос, различается ли обработка `PEN` или формула статуса/боевой модели. Эти примеры **не доказывают**, что формула неверна для боевого симулятора: она может рассчитывать иной показатель или использовать другой вход `profic` и модификаторы. Нельзя выдавать диапазон `damage_min` по цели за диапазон `ATK` в окне героя.

Итог: **универсальная формула для отображаемой минимальной АТК остаётся открытой**, см. Issue #238. Новый код/игровые данные не переписывают формулы MATK, DEF или MAX ATK, не затрагивают сохранения билдов, D1 и Worker.

## Повторный математический аудит по уточнённым 56 зелёного (10.11.2026)

При правильном `thrust=56` прямой перенос `weapon.PEN=80` из JSON в веб-функцию `xa` даёт коэффициент вариации **15%**: минимум **187** при максимуме 219 и **227** при максимуме 266; игровой клиент показывает 189/229 соответственно.

Выявлена **строго исследовательская гипотеза**: у строки АТК в окне персонажа может быть иная база отклонения, эквивалентная `PEN=75` вместо PEN отдельного оружия. Если подставить 75 **только в исследовательский расчёт**, используя формулу `roundHalfEven(PEN / (200 + 6*greenMastery) * 100)`, три независимых снимка совпадают:

| Персонаж | W / PEN в JSON | Зелёное | Игровое окно | Модель с PEN=75 |
|---|---|---:|---|---|
| Энкиду / копьё +8 | 90 / 80 | 56 | 189–219 | 189–219 |
| То же с Боевым кличем | 90 / 80 | 56 | 229–266 | 229–266 |
| Эльф / арбалет | 67 / 90 | 5 | 50–74 | 50–74 |
| Эльф / короткий меч | 9 / 65 | 5 | 9–12 | 9–12 |

`PEN=75` здесь — **подобранная кандидатура, не найденная в исходном коде константа**. Такое совпадение не доказывает, что статусная минимальная АТК игнорирует индивидуальный PEN оружия; возможны другие модификаторы входных параметров и различие между статусным разбросом АТК и боевым разбросом урона. Верная дополнительная проверка — новое оружие с существенно отличающимся PEN при одинаковом зелёном мастерстве и фиксированных остальных параметрах, либо статический анализ клиентского кода, который формирует статус персонажа. До доказательства универсальной формулы **не внедрять PEN=75 в runtime**.
