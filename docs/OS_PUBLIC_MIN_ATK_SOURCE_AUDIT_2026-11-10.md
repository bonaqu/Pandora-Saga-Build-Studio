# Дополнение 10.11.2026 — независимый игровой A/B тест PEN и 41 клиентский диапазон

**Актуальнее предварительных прогнозов ниже.** Пользователь предоставил четыре скриншота одного и того же DRAGOON 45 уровня с одинаковым базовым уроном оружия W90, неизменной зеленью thrust56 и двумя разными значениями PEN. Результаты:

| Оружие +0 | W | PEN | Зелёное thrust | Без «Боевого клича» | С «Боевым кличем» |
|---|---:|---:|---:|---|---|
| Копье Зефира ID1482 | 90 | 80 | 56 | **150–174** | **184–213** |
| Пронзающая пика ID1451 | 90 | 120 | 56 | **136–174** | **167–213** |

Включение бафа не меняет PEN; при замене оружия STR падает с 71 до 70 из-за +1 СИЛ Зефира, но оба значения имеют один порог STR-бонуса. Таким образом максимумы 174/213 совпадают, минимумы различаются; **модель единого PEN=75–77 опровергнута.**

Игровые скриншоты и дополнительные измерения охотника 45 уровня, эльфийки с «Орлиным глазом», подтверждают модель ДВУХ округлений вниз:

```text
D = floor(100 * weapon.PEN / (200 + 6 * trainedWeaponBranchGreen))
minimumATK = maximumATK - floor(maximumATK * D / 100)
```

Проверка против независимых показаний клиента (не против моделируемых билдов):
- **Энкиду / DRAGOON:** 8/8 состояний с PEN80 либо PEN120, +0/+8, STR70/71/72, без бафа/с бафом.
- **Эльфийка / HUNTER:** 24/24 состояний с PEN90, зелёной стрельбой **41**, арбалетами ID2442 W79 и ID2411 W67, до/после +1/+2, СИЛ 6, 20, 22–30. При `54.0(41)/70` используется 41, а не исторически натренированные 54.
- **Энкиду / WARRIOR (Богадур):** 9/9 состояний с коротким мечом ID21, PEN65, зелёным slash5 и СИЛ 9–18.

Итого **41/41 записанных диапазонов** совпали по минимуму и максимуму при подстановке фактически измеренного клиентского MAX. Прошлый единичный сценарий «эльф-лучник, тяжёлый арбалет, 50–74, зелёное 5» пользователь **отозвал как неподтверждаемый и просит не использовать в текущей модели**. Он остаётся только в старых заметках как историческая запись с неподтверждёнными входными данными; не относится к 41 текущим проверенным состояниям.

Важно различать:
- **Клиент:** A/B тест и другие 41 показание, для которых воспроизведён минимум с двумя `floor`.
- **Публичный веб-калькулятор:** опубликованный `xa` использует `roundHalfEven` для `damage_potential` и `floor` для итогового зазора. Это *другая* операция, даже при идентичных PEN и зелени.
- **Гипотеза:** полная универсальность на невиденных игроками ветках (martial, blow, brush, assassin) и комбинациях с нетиповыми модификаторами PEN **пока не доказана**. Синтетические проверки не заменяют реальные игровые измерения.

В исследовательской ветке `research/character-atk-double-floor-20261110` расчёт подключён через `branchMasteries` (действующая зелень, ограниченная потенциалом), `weapon.kind`→ветка, `weapon.PEN`. Он не зависит от ID конкретного предмета, уровня героя, пола, расы или заранее сохранённого диапазона. Для неизвестной категории, отсутствующей зелени либо PEN он оставляет минимум `null`. К основной ветке изменение подключать только после успешного CI и независимой проверки на других категориях оружия. Issue #238 следует держать открытой для расширения доказательной базы.

## Аудит 0.598.0 — отмена специальных min–max в пользу общей формулы

По замечанию владельца пользовательский runtime не должен подставлять min–max только для конкретного билда. В релизе 0.598.0 удалены все наблюдавшиеся индивидуальные таблицы минимума из `pandora-os-character-calculator.js`. Проверенные 189–219/229–266, 9–12 и 50–74 **сохранены как независимые экспериментальные эталоны**, а в Книге героя пока показывается вычисленный универсально максимум АТК без непроверенной нижней границы.

Впервые удалось прочитать публичный JS актуального калькулятора OS:
https://pandorasaga-os.com/assets/BuildCalculator-DgAOFedT.js

В функции `xa(abilities, level, weapon, profic, tables.weaponPlus, modifiers)`:
- `damage_rate` = физическая атака по опубликованной формуле силы, + заточка, + источниковые плоские и % бонусы;
- `damage_potential` = `roundHalfEven(effectivePEN / (200 + 6*weaponProficiency) * 100)`, где `effectivePEN` включает `weapon.PEN` и эффекты пробивания;
- `damage_min` = `damage_rate - floor(damage_potential * damage_rate / 100)`;
- `damage_max` = `damage_rate`.
Карта оружия→ветка: `1H_SWORD,2H_SWORD,1H_TRUMP_WEAPON -> slash`; `1H_AXE,2H_AXE -> brush`; `1H_BLUNT_WEAPON,2H_BLUNT_WEAPON,WAND,STAFF -> blow`; `POLE_ARM,LANCE -> thrust`; `BOW,CROSSBOW -> archery`; `2H_TRUMP_WEAPON -> assassin`; `BARE_HAND,MARTIAL_WEAPON -> martial`.

Сравнение с **окном персонажа реальной игры** не совпало без дополнительных объяснений:
- Heavy Crossbow ID2411: `PEN=90`, предполагаемое `archery=5`, `damage_max=74`. Публичная `xa` даёт `roundHalfEven(90/(200+6*5)*100)=39` и `74-floor(74*.39)=46`, клиент показывает **50–74**.
- Zephyr Spear ID1483: `PEN=80`, по уточнённому скриншоту Колющий показывает **56.0(56)/90**: зелёное 56, потенциал 56, предел 90. При `thrust=56`, `damage_max=219` текущая `xa` даёт `roundHalfEven(80/(200+6*56)*100)=15`, `219-floor(219*.15)=187`, тогда как игровой клиент показывает **189–219**. С кличем она даёт 227–266 вместо 229–266. Это оставляет открытым вопрос, различается ли обработка `PEN` или формула статуса/боевой модели. Эти примеры **не доказывают**, что формула неверна для боевого симулятора: она может рассчитывать иной показатель или использовать другой вход `profic` и модификаторы. Нельзя выдавать диапазон `damage_min` по цели за диапазон `ATK` в окне героя.

Итог: **универсальная формула для отображаемой минимальной АТК остаётся открытой**, см. Issue #238. Новый код/игровые данные не переписывают формулы MATK, DEF или MAX ATK, не затрагивают сохранения билдов, D1 и Worker.

## Повторный математический аудит по уточнённым 56 зелёного (10.11.2026)

При правильном `thrust=56` прямой перенос `weapon.PEN=80` из JSON в веб-функцию `xa` даёт коэффициент вариации **15%**: минимум **187** при максимуме 219 и **227** при максимуме 266; игровой клиент показывает 189/229 соответственно.

Выявлена **строго исследовательская гипотеза**: у строки АТК в окне персонажа может быть иная база отклонения, эквивалентная `PEN=75` вместо PEN отдельного оружия. Если подставить 75 **только в исследовательский расчёт**, используя формулу `roundHalfEven(PEN / (200 + 6*greenMastery) * 100)`, три независимых снимка совпадают:

| Персонаж | W / PEN в JSON | Зелёное | Игровое окно | Модель с PEN=75 |
|---|---|---:|---|---|
| Энкиду / копьё +8 | 90 / 80 | 56 | 189–219 | 189–219 |
| То же с Боевым кличем | 90 / 80 | 56 | 229–266 | 229–266 |
| Эльф / арбалет | 67 / 90 | 5 | 50–74 | 50–74 |
| Эльф / короткий меч | 9 / 65 | 5 | 9–12 | 9–12 |

`PEN=75` здесь — **подобранная кандидатура, не найденная в исходном коде константа**. Такое совпадение не доказывает, что статусная минимальная АТК игнорирует индивидуальный PEN оружия; возможны другие модификаторы входных параметров и различие между статусным разбросом АТК и боевым разбросом урона. Верная дополнительная проверка — новое оружие с существенно отличающимся PEN при одинаковом зелёном мастерстве и фиксированных остальных параметрах, либо статический анализ клиентского кода, который формирует статус персонажа. До доказательства универсальной формулы **не внедрять PEN=75 в runtime**.

## Контроль, позволяющий отделить постоянный диапазон от weapon.PEN (новая находка)

По публичным `items.json` существуют **два подходящих Всаднику (DRAGOON) древковых оружия без заточки**, при этом их базовая W одинаковая:
- «Копье Зефира» ID **1482**: `kind=POLE_ARM`, `W=90`, `PEN=80`, эффект `СИЛ +1`; при предыдущем полном комплекте тестера СИЛ **71**;
- «Пронзающая пика» ID **1451**: `kind=POLE_ARM`, `W=90`, `PEN=120`, эффектов на характеристики **нет**; при том же комплекте СИЛ **70**.

У СИЛ70 и 71 совпадают `floor(STR/2)=35` и порог оружейного бонуса `+24%`. Оба +0 оружия при прочем неизменном комплекте дают **предсказанный максимум 174** (для ID1482 без клича максимум 174 подтверждён тестером). Расовая пассивка «Сильные руки» действует на оба типа `POLE_ARM`. При замене нужно снять/не устанавливать души оружия в оба сравниваемых экземпляра и убедиться, что никакие временные усиления не действуют.

Различаются механики следующего ранга:
- Если строка АТК использует **индивидуальный PEN оружия** согласно публичной `xa` (`thrust=56`): для ID1482 прогноз **148–174**, для ID1451 **136–174**.
- Если в строке АТК используется **одна общая эквивалентная база 75–77** при том же округлении: у обоих прогноз **150–174**.

Все числа нижней границы здесь — математические предсказания **конкурирующих гипотез**, не игровые результаты. При неравном максимуме или дополнительном эффекте проверка недействительна: необходимо записать реальную СИЛ, зелёное мастерство, обе границы АТК, состав снаряжения и отсутствие «Боевого клича».

Этот A/B тест гораздо эффективнее прокачки нового героя: один класс, одна ветка навыка, одинаковые W и порог СИЛ, но разные `PEN`. Однако для *доказательства* общей модели дополнительно понадобятся другие значения mastery/вторая категория оружия или исходный клиентский код. **Не вставлять предсказанные числа в пользовательский движок**.
