# Книга героя: восстановление расчётных показателей ударов текущего билда (0.757.0)

## Причина изменения
Существующий `directStrikeCoefficientPreview` в `pandora-os-character-calculator.js` уже проверяет конкретные игровые ID, `EP_ONHIT_DAMAGE_SCALE` и наличие действия атаки, профессию, уровень, освоенное зелёное мастерство, требуемое оружие и переходы на улучшенные навыки. По состоянию на закреплённые файлы OS таких **19 изучаемых исходниковых вариантов**. При расчёте Skill Effects результат включается в `offense` с `amount:null` (итоговый урон не доказан), а `coefficientModels[0].amount` — числовой показатель по мастерству.

Но прежний фильтр `skillEffectsPage` оставлял только модели с `roundingParts`, которыми снабжены расчёты стихийной магии, не физические удары. Поэтому уже рассчитанное по текущему билду число не доходило до пользовательского интерфейса.

## Что видит игрок
Для доступного умения в Книге героя → Эффекты умений → Атакующие умения:
- игровое название RU/EN и оригинальная иконка по тому же ID;
- `—` вместо неизмеренного финального урона цели;
- отдельную подпись **«Параметры умения: Сила удара (расчёт) ±N%»** (EN: Estimated strike strength);
- существующее раскрываемое базовое применение (стоимость ОМ/время/откат) для подтверждённого активного источника.

Вывод следует `skill.available===true`, а значит не включает недостижимое зелёное мастерство, неподходящее оружие и классы без навыка. Число не умножает молча общую атаку, не прибавляет повторные пакеты урона и не объявляется живой серверной цифрой.

### Пример
Джаггернаут, Рубящий 40, `1H_AXE`: **«Критический удар»** `142002001` (официальное EN **Clobber**) → коэффициентная модель **+20%**, но финальный урон **неизвестен**. При несовместимом оружии эта модель недоступна текущему персонажу. Расчёт с текущими FV1 и независимым округлением в калькуляторе, а не утверждение об уроне по конкретной цели.
