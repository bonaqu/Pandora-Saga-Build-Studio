# 0.808.0 · Приёмка автоматического резерва GitHub после обновления каталога

**Область:** `Pandora Saga Build Studio`, продакшен-ветка `bonaqu_projects`, Worker `ps-build-studio-cloud`. Продолжение issue #615 (исходный #616 закрыт как дубликат).

## Обязательная цепочка одного подтверждения

1. Администратор выбирает изменения и подтверждает применение в админке (не требуется отдельный клик по «Создать PR»).
2. До создания каких-либо записей каталога в D1 браузер делает **авторизованный read-only** запрос `GET /api/admin/catalog/github-status`; сервер проверяет действительность GitHub токена и подтверждённое право записи. Если статус не `{configured:true,connected:true,writeAccess:true}`, операция **прерывается без D1 изменений**.
3. Снимок каталогов проходит существующие структурные и модельные проверки, загрузку всех 17 наборов в D1, CAS-публикацию и 17/17 публичный read-back. Прежний snapshot не портится.
4. Та же публикация автоматически вызывает `POST /api/admin/catalog/github-pr`. Создаётся data-only PR либо сообщается, что архив уже совпадает; GitHub Actions сам проверяет Node+Chromium и принимает PR при двух зелёных точных SHA. Ручная кнопка в админке остаётся **только аварийным повтором**.
5. Если на GitHub создана ветка `catalog/snapshot-ps-…`, но не создан PR, повторный запрос восстанавливает PR лишь после проверки parent base SHA, ограниченного Git diff и всех SHA-1 Git blobs против текущего опубликованного снимка D1. Неосмысленные или изменённые вручную ветки остаются без изменений.

## Ограничения и доказательства

- `wrangler secret list --format json` от 15.11.2026 подтверждает **наличие имени** `GITHUB_CATALOG_TOKEN` в production (Actions run [43723495149](https://github.com/bonaqu/Pandora-Saga-Build-Studio/actions/runs/43723495149)); значения секретов не экспортируются. Это не равно доказанным правам GitHub — они проверяются авторизованным preflight.
- При обрыве после CAS-публикации резерв не считается завершённым, пока GitHub не ответил успешным созданием PR/доказанным совпадением. Автоматическое восстановление работает при повторном вызове в том же сеансе; абсолютную гарантию при многодневном простое GitHub без durable-очереди не заявляем.
- Отсутствие редактора при закрытии браузера после D1 commit может прервать вызов резервного PR. Нужен отдельный серверный надежный background delivery для гарантии вне браузера; этот релиз не обещает фоновое выполнение.
- Новая неизвестная семантика навыков не может автоматически стать верной вычисляемой формулой по одному обновлённому JSON; действует pre-publication compatibility warning #615.
