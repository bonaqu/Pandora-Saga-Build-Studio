# Разделение навыков в энциклопедии — 7 ноября 2026

Цель: на первом экране «Навыков» показывать подтверждённые умения персонажа, не смешивая их со служебными эффектами и техническими версиями, но не терять доступ к исходным записям. Критерий «есть картинка» не определяет игровую доступность.

## Семь фильтров

| Фильтр RU / EN | Условия |
|---|---|
| Умения персонажа / Character skills | `learnable===true`, хотя бы одна явная разрешённая профессия (`classes`), не ветки `special/race` |
| Гильдия и осада / Guild and siege | Структурные записи ветки `special` с префиксами ID `600`, `610` и `620`. Включает гильдейские ранги и осадные инструменты, но не выдаёт записи за обычные изучаемые умения |
| Особые умения / Special skills | Записи с назначенными профессиями, которые не подтверждены как обычные изучаемые навыки; не трактуются автоматически как активные |
| Варианты навыков / Skill variants | Скрытые ранее канонизированные записи или дополнительные записи с названием подтверждённого навыка персонажа, даже при ошибочно/неполно выставленном `learnable`; не затрагивает гильдию и осаду |
| Прочие записи / Other records | Системные записи, статусы из технической ветки `race` (например, Сон и Оглушение), неизвестные и прочие неподтверждённые навыки; это не расовые пассивки персонажа |
| На проверке / Under review | **Независимый срез** всех навыков, у которых нет доступного локального оригинала, одобренной иконки-донoра по `displayAliases` или собственной иконки администратора. Тот же игровой знак вопроса, что в списке |
| Все навыки / All skills | Все записи с их исходными ID, без деструктивной дедупликации |

Категории взаимоисключающие, кроме независимого среза **«На проверке»** и **«Все навыки»**.

Гильдейские звания I, II и т.д. **не становятся дублями**, даже если совпадают рисунки. Для варианта персонажа приоритет всегда у `learnable===true` с подтверждённой доступностью профессии.

В сохранённом `data/os/skills.json` на момент разработки: **569 записей**; **234** помечены `learnable:true`, из них **232** имеют явно назначенные профессии. Числа отображаемых групп вычисляются из загруженного реального каталога (D1 или архивной копии) и могут отличаться.

## Дополнительная проверка источников и навигации (0.403.0)

- «Помощь ветра» `260006002` и «Храм» `310023002` имеют `learnable:true`, но пустой список разрешённых профессий. По совпадению имени с подтверждённой доступной версией они теперь относятся к **вариантам**, а не к обычным навыкам персонажа; исходные параметры обеих версий доступны по своему ID.
- Внутренние записи `branch:race` с названиями «Сон», «Оглушение» и подобными хранят статусные/служебные эффекты, а не выбираемые расовые пассивки. Для них более точная группа — «Прочие записи».
- Прямые ссылки на варианты из поиска, других разделов и браузерной истории сохраняют исходный ID даже после перезагрузки страницы. Канонизация монстров, предметов и других разделов осталась прежней.
- Выбранный фильтр навыков теперь входит в навигационное состояние вкладки и сохраняется между возвращением назад, переходами и перезагрузкой. Отсутствующая иконка `skill_unknown.webp` одинаково отображается при наличии записи навыка как в live D1, так и в явно выбранном архивном режиме. Источник оригинала никогда не подменяется.
- Распределение иконок в сохранённой версии: **59** записей навыков остаются без собственного/общего изображения; в интерфейсе для них показывается вопросительный знак. Остальные 201 переиспользуют локальный оригинал для отображения, исходный реестр 264 пропусков не пересматривается.

## Неопределённые совпадения внутри самих изучаемых умений

Дополнительный анализ 569 записей источника выявил **19 названий**, у которых `learnable:true` и назначенные профессии указаны сразу у **41 записи**. Во всех 19 группах множества профессий хотя бы частично пересекаются. Примеры: «Блокирование», «Первая помощь», «Маскировка», «Яд», «Лечение», «Магический щит». Метаданные ещё **не доказывают**, какие версии сейчас действуют на реальном сервере и можно ли их скрыть без потери работающего умения.

Поэтому эти записи **не удалены и не слиты насильно**: у них могут быть различные требования, действие и параметры. Воспроизводимый внутренний отчёт: `npm run skills:duplicates` (`scripts/report-skill-identity-overlaps.mjs`). В отчёте у каждой записи сохранены исходная ветка, доступные профессии, требуемый уровень, параметры и ссылки `EP_SKILL_EXEC`, если они есть. После проверки в игре конкретную пару можно будет отнести к вариантам на основании доказательств, а не общей строки названия.

## Уточнение названия фильтра и ссылок (0.404.0)

- Название фильтра изменено с технического **«Без изображения»** на пользовательское **«С иконкой „?“»** (`With “?” icon`). Это выбор по **видимому игровому вопросительному знаку**, а не утверждение о доступности умения. Вкладка содержит все записи, для которых система действительно показывает эту заглушку; количество рассчитывается по текущему каталогу.
- Ссылки на навыки и их требования больше не перенаправляют дополнительный ID на основную одноимённую запись. Название может совпадать, но параметры и эффекты могут различаться; переход сохраняет конкретную версию. Канонизация других разделов не меняется.
- Добавлены точные регрессионные тесты ссылок в Node и отображения RU/EN в Chromium.

## Защита фильтра при недоступном реестре изображений (0.405.0)

Фильтр **«С иконкой „?“»** должен отражать реально показанный значок, а не только записи в `os-icon-manifest.json`. Если реестр не загрузился, сайт сам показывает вопросительный знак вместо всех не подтверждённых локально иконок. Ранее фильтр при этом показывал **0** навыков, что противоречило фактическим иконкам списка.

Исправлено: пока реестр недоступен, все записи навыков без индивидуальной админской картинки входят в этот фильтр. После успешной загрузки манифеста он автоматически уточняется до фактического набора (в архивном снимке **59** записей). Новые записи D1 без `iconId` также правильно попадают в фильтр, даже если есть одноимённый навык с подтверждённой иконкой: текущий рендерер без `iconId` действительно показывает «?».

Проверки Node и Chromium включают явную симуляцию отказа запроса реестра. Никаких сетевых подстановок игровых изображений не добавлено.

## Редактирование всех подписей фильтров (0.406.0)

- «С иконкой „?“» заменено на более нейтральное «На проверке» (EN: `Under review`). Это **подборка навыков без подтверждённой картинки**, а не статус игровых способностей. Названия других категорий не поменялись.
- В редакторе рядом с выпадающим фильтром доступна одна небольшая ✎. Она раскрывает **все семь** подписей, каждую можно отредактировать двойным кликом по тексту или кнопкой ✎ в строке, без модального окна. Enter/выход из поля — сохранить, Escape — отменить.
- Названия хранятся раздельно для RU и EN в уже существующем `guideedit.wiki.labels` Cloudflare D1 под ключами `skill_filter_<stable_category>_ru/en`. Идентификаторы `player/guild/special/variants/other/unknown/all`, сами правила отбора, количество записей, прямые ссылки и игровые данные от переименования не меняются.
- Проверку нового поля расширили **в трёх независимых местах**: `PandoraWikiLabels.validPatch`, `PandoraHonorGuide.validOverride` и production Worker. Полный набор всех возможных подписей содержит 42 RU/EN записи; лимит структуры увеличен с 28 до 50 (максимальная длина одной подписи — 90 символов).
- Нативные HTML `<option>` нельзя редактировать полями ввода, поэтому используется обычный выпадающий список для выбора и отдельная компактная раскрывающаяся панель исключительно при активном режиме администратора. После сохранения видимая подпись в списке меняется без сброса выбранной категории.
- Worker публикуется собственным workflow отдельно от GitHub Pages; успешные тесты ещё не подтверждают сохранение в production D1. Реальное сохранение проверяется только после успешного развёртывания Worker и действия администратора.

## Архитектура

- `pandora-studio-wiki-skill-filters.js`: чистая модель классификации, без изменений игровых данных, формул или D1.
- `pandora-studio-encyclopedia-data.js`: опциональный режим `includeVariants` для поиска по *всем* исходным ID. Существующее каноническое отображение, используемое другими разделами, остаётся совместимым.
- `pandora-studio-app.js`: один компактный выпадающий фильтр в существующей строке управления, рядом с поиском. Сохранены прокрутка, поиск RU/EN, нумерация результатов и ссылки. По прямой ссылке открывается нужная категория.
- `assets/os-icon-manifest.json`: подтверждённые 1173 оригиналов, 264 отсутствующих и 201 отображаемое переиспользование **не изменяются**.
- Предоставленные пользователем инструменты извлечения клиента и игровые архивы не публикуются на GitHub автоматически.

### Неопределённость

`learnable` и `classes` отражают известные поля каталога. Они не гарантируют, что способность исполняется на текущем сервере, а отсутствие таких признаков не доказывает обратного. Данные `branch:special` структурно разделены по префиксам текущих каталогов, а не произвольно по рисунку или названию.

Ничего не удаляется, не меняется в серверных данных и не объединяется в формулах. При появлении новых доказательных сведений классификатор может быть уточнён отдельно от индекса навыков.
