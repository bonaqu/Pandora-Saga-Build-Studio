# Данные D1 и резервной копии: отличия форматирования описаний

Дата проверенного фактического расхождения: **17 ноября 2026 года**.

В открытых read-only API `https://pandorasaga-os.com/gamedata/items.json`
и `https://ps-build-studio-cloud.bonaqu.workers.dev/api/catalog/items.json`
часть описаний **слита в строку без** исходных `<br>`.
В резервном `data/os/items.json` переносы сохранены; после PR #681
все игровые поля 1140 предметов совпали с upstream, но **858**
описаний остались иначе оформлены. Для душ — **15** описаний.
Английские записи `stringsEn` имеют аналогичные отличия.

До данного исправления `describeDescriptionDrift(local, d1)` считал
`lineBreaks` только в случае, когда D1 содержит `<br>`, а архив
не содержит. В реально обнаруженном обратном случае эти элементы
неверно попадали в `otherText`.

Теперь счётчик `lineBreaks` распознаёт **оба направления** утраты
разрывов. Аналогично распознаются `<b>` и исчезнувшие `<item N>`
в обоих направлениях. Изменение игрового числа, текста, ID предмета
или целевой ссылки с одного `<item ID>` на другой классифицируется
как `otherText`, **не** как безобидная разметка.

Это **только диагностика**. Ничего не заменяется в D1, source JSON,
локализациях или пользовательских билдах. `compareCatalog` остаётся
точной проверкой: даже исключительно оформительские отличия
по-прежнему вызывают `equal:false`, а read-only parity по-прежнему
сообщает `FAIL`, не скрывая изменений. Не вводить автоматическую
публикацию D1, обход CAS или непроверенные игровые формулы.

Тесты покрывают обе последовательности (rich→flat, flat→rich),
настоящий фиксированный набор 30 HTML-описаний из архива,
русские и английские подписи, реальное изменение чисел и
ссылок на предметы и неизменность обоих входных объектов.
