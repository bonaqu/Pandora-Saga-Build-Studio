## Матрица редактирования энциклопедии по существующим обработчикам

| Раздел | Доступный интерфейс администратора | Ещё надо доказать |
| --- | --- | --- |
| Предметы | RU/EN имя/описание, эффекты, характеристики, совместимость, источники, обмены | полный CRUD для всех типов источников; устойчивость к конфликтам D1 |
| Сундуки | описание/название, группы наград, количество, шанс и вложенные шкатулки | игровая семантика 100%-записей и всех альтернатив |
| Монстры | RU/EN текст, характеристики, сопротивления, обычный/особый дроп, связи с локациями | owner-created монстры и числовые dropedit имеют разные модели; объединить |
| NPC | RU/EN текст, назначение, местоположение, торговые рецепты/стоимость/материалы/NPC | удаление и повторное добавление связей на реальной D1, транзакционная целостность |
| Локации | RU/EN названия/описания, NPC, монстры, теги, дополнительные разделы | полнота данных за пределами Астира; точность игровых ссылок |
| Подземелья | RU/EN имя/описание, список монстров | проверка смены связей после сохранения и F5 |
| Умения | RU/EN имя/описание, числовые параметры, мастерство, предварительные условия, классы | полный соответствующий живой расчёт, не угадывать игровую механику |
| Души | RU/EN имя/описание, слоты, стоимость | проверить все игровые эффекты и связь с источником получения |
| Книга героя | текстовые пользовательские пояснения, регулируемые усиления | не смешивать пользовательские расчётные параметры с игровыми исходниками |
| Происхождение / Путь героя | настройки героя, классы, расы, очки, мастерство и навыки | не путать локальное редактирование билда с записью глобального каталога |

В каждом разделе редактору показывают игровые названия, внутренние ID — только
служебный механизм сохранения; новый интерфейс выбора NPC по имени снижает
риск ошибок. Наличие UI недостаточно для объявления полноты — нужны браузерные
проверки с моками и отдельные авторизованные production проверки.

## Проверка production D1

- Read-only health и release readiness выполняются в GitHub Actions.
- `/api/admin/catalog/test-write` теперь доступен авторизованному владельцу
  напрямую в панели; вызывает вставку/чтение/удаление временных qa-записей.
- Наличие кнопки, зелёных unit-тестов или read-only CI **не подтверждает**
  фактического запуска записи в production. Для этого нужен отдельный
  успешный ответ защищённого endpoint на живом Worker.
- Действующие учетные данные, билды пользователей, основные каталоги и
  таблица `catalog_current` не должны изменяться при проверке.
