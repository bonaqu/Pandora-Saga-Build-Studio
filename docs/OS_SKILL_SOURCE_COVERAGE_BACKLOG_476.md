# #476 — Очередь исследования непокрытых формулами умений

**Проверяемая цель:** не смешивать отсутствие расчёта эффекта с недоступностью умения, классом, скрытой дочерней записью или исходными параметрами без доказанной игровой формулы.

## Запуск

```bash
node scripts/audit-os-skill-coverage-backlog.mjs
node scripts/audit-os-skill-coverage-backlog.mjs --all
node --test tests/os-skill-coverage-backlog-476.test.mjs
```

Команда заново строит существующий аудит `skills:formula-audit` для **всех текущих 571 записей** и граф исходных `EP_*_EXEC`-ссылок. В отдельную очередь попадают только `unmodeled-learnable` и `source-access-limited` — без включения уже численно смоделированных, пассивных, внутренних и триггерных записей в «пробелы». Реестр содержит текущие исходные ID, русское имя, тип, класс, требования, семейства эффектов, известные дочерние/родительские связи. Режим `--all` дополнительно возвращает **все оригинальные fv1/fv2 по отдельным строкам**.

## Категории (взаимоисключающие)

- `source-cap-candidate`: умение назначено хотя бы одному классу и уровень/требования **не превосходят** лимиты исходного каталога на 55-м уровне. Это **не подтверждение реально возможного билда**: могут существовать условия предшествующего умения, оружия, точки получения, ограничение очков и другие правила.
- `source-cap-limited`: есть исходные классы, но ни один не удовлетворяет только рассматриваемому набору ограничений. Это **не доказательство невозможности активации** игровым сервером.
- `no-source-class-assignment`: `learnable:true`, но ключей классов в исходной записи нет. Не означает, что запись бесполезна: может существовать другой способ получения или вызова.
- `wiki-access-limited`: имеющаяся в Энциклопедии верифицированная по форме исходника подсказка о доступе; не выдавать её за боевой числовой результат.

`families` сортируется **по числу источников с кандидатами в исходных лимитах классов**, а затем по общему числу ID. Это только порядок *проверки недостающих знаний*, не рейтинг важности навыков, силы эффекта или надёжности игровой формулы.

## Производственная безопасность

Аудит выполняет только чтение локального `data/os/skills.json` и `data/os/classes.json`. Не выполняет HTTP и SQL, не редактирует D1, не создаёт пользовательский билд, не вносит исходные числа в книгу героя. Перепроверка совместимости прошла отдельно: [публикация 0.959.0 и read-only проверка 16/16 datasets](https://github.com/bonaqu/Pandora-Saga-Build-Studio/actions/runs/45880125953) — источник D1, включая **571/571 записей skills**, совпал с опубликованным снапшотом. Это **доказательство согласованности каталога**, не подтверждение обработки `EP_*` текущим сервером игры.

### Дальнейшие исследования

Для наиболее частых семейств в `source-cap-candidate` собирать отдельный Source Evidence Record: skill ID, `EP`, `fv1/fv2`, цель, условия/уровень, независимый источник про конкретные параметры и их единицы, затем расчётный тест-вектор и статус `modeled` / `verified`. Не конструировать итоговый урон, шанс срабатывания или округления из совпадения ненулевых позиций.
