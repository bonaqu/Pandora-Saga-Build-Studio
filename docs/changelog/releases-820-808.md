# История релизов · 0.820.0—0.808.0

## 0.820.0 — 2026.11.15.820 · Внутренние действия и материалы ловушек до D1

- Предпубликационный `PandoraCatalogSafety.replaySkills` теперь отслеживает не только `prereq`, но и реальные связи `EP_SKILL_EXEC`, `EP_ONHIT_SKILL_EXEC`, `EP_ONHIT_SKILL_EXEC_CHANGE_BA`, `EP_SKILL_EXEC_COUNT` по подтверждённым ID. Связность строится для старого и выбранного каталогов; зависимый корень перепроверяется даже при изменении внутреннего действия с `classes:{}` и `prereq:null`.
- Помимо ранее поддерживаемых боевых числовых моделей replay контролирует существующие источниковые расходы ловушек `trapSkillCostPreview`: количество расходного предмета и известный улучшенный вариант 50 уровня. Это проверка материалов в Энциклопедии, не выдуманный урон ловушки.
- Отдельные регрессии: Полное исцеление и его внутренние коэффициенты сопротивления, все пять проверенных исходов ловушек, связка особой Взрывающейся ловушки с внутренним ID, fast path переводов, динамическая FV и неизменность старого/выбранного JSON.
- Данные исходного каталога и D1 не изменяются. Строгий отказ при утрате ранее показанного числа остаётся до D1 CAS. После Node и Chromium CI проверка Pages/Worker и 16 опубликованных датасетов D1 в режиме чтения.

## 0.819.0 — 2026.11.15.819 · Названия навыков не определяют игровые механики

- Удалены зависимые от русских подписей source-gates в уже проверенных моделях: внешнее «Ободрение», Полное исцеление с внутренним действием, on-hit и Песчаная буря, связанные исходы ловушек и улучшенная Взрывающаяся ловушка Загонщика.
- Вместо совпадения названий проверяются канонические идентификаторы, ветки `branch/branchRaw`, типы/статусы изучения, реальные дочерние действия и известные числовые FV/EP контракты. Переименование RU-текста не выключает игровые формулы, но изменение игровых источников по-прежнему отвергается.
- Для «Ободрения» усилена проверка всех трёх `FV2` и полной структуры эффектов: неизвестная дополнительная механика не наследует старый бонус к СИЛ, ЛВК и ИНТ.
- Регрессии на текущем каталоге: независимое переименование родительских/внутренних навыков, сохранение эффектов и требований, замены веток, неизвестные FV2, проверка data-only статусов. Изменённые прежние тесты теперь проверяют реальную механику, а не перевод как числовой контракт.
- Production D1, Worker, CAS, auth и билды не меняются. Node + Chromium на точном PR SHA, затем Pages и read-only Worker/D1 parity.

## 0.818.0 — 2026.11.15.818 · Контроль бафов союзников и жреца перед D1

Теперь проверяются Бафы от союзников (Боевой клич, Массовая сосредоточенность, Помощь ветра, Благословение ветра, Божественное благословение, Благословенный покой) и коэффициентные усиления внешнего жреца.
- Каждый подтверждённый старый числовой результат привязан к конкретному идентификатору исходного навыка и его уже существующей модели, включая три Чары усиления, взаимодействие Священного оружия/Чар и составные действия Песни мира, Песни поэта и Песни чар.
- Для песен проверяются и не изучаемые напрямую дочерние действия (340003003, 340001003, 340004003), у которых нет классов для обычного прогона билдов. Потеря прежде рассчитанного эффекта блокирует публикацию до D1 CAS.
- Тесты используют текущий игровой `data/os/skills.json` и действующий калькулятор; неизвестным FV/EP не приписывают механики. Чисто текстовые изменения не запускают ненужный пересчёт; снимки не изменяются.
- Без изменений Worker, схемы/данных D1, CAS, авторизации, библиотеки билдов. Merge только после Node + Chromium, затем live read-only Pages/Worker/D1 parity.

## 0.817.0 — 2026.11.15.817 · Безопасные связи родительских и улучшенных навыков

- В существующих моделях повышений умения совпадение локализованных имён заменено на проверку **точного prerequisite ID и совпадающего branch/branchRaw/skillType**, доступности родителя текущему классу и его learnable-флага. Переименование родительского навыка само по себе больше не скрывает расчёт улучшенной версии.
- Предпубликационный `replaySkills` теперь транзитивно включает дочерние навыки по графам **старого и выбранного** каталога: изменение, удаление или ограничение родителя не может оставить его дочернюю числовую модель без проверки.
- На реальных данных проверены обе версии «Магического щита» и «По следам ветра», изменение ветки/типа, удаление родителя, ограничение профессии, сохранность чисел и неизменность снимков.
- Правило остаётся fail-closed: новая семантика механики и неподтверждённые эффекты требуют согласования; D1/Worker/CAS/auth и пользовательские билды не менялись.
- Node + Chromium на точном PR SHA обязательны перед merge; после релиза — Pages и read-only Worker/D1 parity.

## 0.816.0 — 2026.11.15.816 · Защита составных навыков и полный контроль коэффициентов

- После изменения игровых данных контрольный пересчёт проверяет **каждую числовую модель EP** навыка, включая несколько независимых коэффициентов при неопределённом общем эффекте. Пропажа любого ранее рассчитанного параметра блокирует применение снимка до записи в D1.
- У улучшенного «По следам ветра» (420004002, Заклинатель 50+) зарегистрирована только переменная основная модель FV1; дополнительный EP_ALL_RESISTANCE_CONST должен точно совпадать с проверенным исходником и оставаться численно доступным. Изменения FV2, дополнительных эффектов и времени применения не получают статус совместимых автоматически.
- В предварительной проверке skills только тексты и иконка считаются справочными изменениями. Время применения, перезарядка, мана, дальность и **любые неизвестные игровые поля** требуют просмотра механики; те же изменения проходят регрессионный replay.
- Добавлены сценарии на реальных данных для двойного эффекта ветра, мультикоэффициентных Чар усиления, потери второго параметра при изменении cast и новых source-полей. Совместимость новых серверных формул не предполагается.
- Выпуск разрешён только после Node и Chromium CI, затем проверки опубликованного Pages и read-only Worker/D1. Production D1, CAS, аккаунты и билды не изменяются.

## 0.815.0 — 2026.11.15.815 · Динамические коэффициенты подтверждённых навыков

- Для четырёх конкретных, уже существующих числовых превью добавлен декларативный контракт источниковых FV: Поглощение стихий, Магический щит (две версии), По следам ветра (базовая версия). При неизменных EP-коде, FV2, зарезервированных параметрах, дополнительных эффектах и других свойствах калькулятор берёт новые значения FV1 без прежнего жёсткого сравнения на конкретный старый вектор.
- Перед CAS-публикацией выбранных изменений `verifiedDynamicSkillFV` прогоняет **действующий** калькулятор по доступной профессии, мастерству и уровням 45/55. Если оба варианта действительно рассчитываются и числовой результат меняется вслед за источником, статус — «проверено моделью». При неизвестной механике/несоответствии контракту — «нужна проверка»; старая поддерживаемая модель не может тихо исчезнуть благодаря `replaySkills`.
- Бой, живой сервер и полный набор неизвестных механик не объявляются подтверждёнными. Навыки с дополнительными Remaked-бафами, вероятностями и дочерними effect chains сохраняют строгие источниковые проверки. D1, Worker, CAS, GitHub backup и пользовательские сохранения не менялись.

## 0.814.0 — 2026.11.15.814 · Проверенные числовые значения Forth до публикации каталога

- Изменения улучшений `itemForth` теперь классифицируются **по конкретному предмету**, не целой таблицей. При неизменных ступенях заточки, EP-кодах, направлениях, дополнительной компоненте `b` и всех остальных механических условиях замена только числового `a` получает статус поддержки калькулятором, если действующие модели действительно читают оба варианта на всех уровнях +0…+10.
- Новые ступени, неподдерживаемые эффекты, смена свойств/типа предмета вместе с Forth и изменение иных коэффициентов по-прежнему требуют проверки механики. Отдельный строгий fail-closed replay из 0.813 запрещает потерю ранее рассчитываемого EP до записи в D1.
- Новые регрессии выполняют реальную числовую функцию `gatherEffects` для улучшения ID 242, проверяют неизвестный код, изменение `b`, новый порог и смешанный выбор с предметом 243. Исходные снимки не изменяются.
- CAS, GitHub backup PR, D1, аккаунты и пользовательские сохранения не менялись; выпуск через Node/Chromium и публичную read-only проверку Pages/Worker.

## 0.813.0 — 2026.11.15.813 · Контракты числовых эффектов душ и Forth до D1

- Поддерживаемые калькулятором изменения числового параметра `a` в старых `EP_*` предметов и душ распознаются по фактическим источниковым каналам, а не по любому совпавшему названию. Все остальные поля и границы заточки сохраняются, для изменённого эффекта проверяются активные улучшения +0…+10. Неизвестные игровые коды не объявляются работающими.
- Добавлена независимая read-only проверка `replayEquipmentEffects`: если раньше действовавший числовой бонус заменён неподдерживаемым `EP_*`, публикация точного выбранного снимка блокируется **до D1**. Проверка повторяется в `prepare()` даже после успешного визуального предпросмотра. Явно удалённый бонус остаётся согласуемым изменением источника, а не автоматической ошибкой.
- Регрессионный набор проверяет настоящие предметы, души, Forth и контрольный многоэлементный сценарий вычисления героя. Нет нововведённых формул урона, неизвестных шансов/длительностей или автоматического изменения пользовательских билдов.
- Выпуск: обязательные Node + Chromium на SHA, публикация Pages и read-only контроль Worker/D1. Глобальная задача #615 остаётся открытой до полного подтверждения игровых механик.

## 0.808.0 — 2026.11.15.808 · Синхронизация GitHub без отдельного действия

- **До любых записей в D1** «Применить выбранные изменения» проверяет через авторизованный Cloudflare Worker, что серверный GitHub-токен подключён и имеет подтверждённое право записи в целевой репозиторий. Наличие одного имени секрета недостаточно: при неудачной/неизвестной проверке публикация не начинается и объясняет причину. Без ручного GitHub-копирования после успешного обновления.
- После D1 read-back по-прежнему автоматически создаётся резервный PR; он объединяется строго после Node и Chromium на одном точном commit SHA и только для разрешённых game-data JSON.
- Прерванная отправка PR теперь восстанавливается автоматически, если GitHub уже создал ветку, но запрос/PR оборвался. Для восстановления Worker проверяет parent SHA текущей GitHub ветки, отсутствие любых изменений кода и точное побайтовое SHA-1 соответствие **всех 17 JSON** актуальному опубликованному снимку D1. Любое расхождение блокирует восстановление.
- При потерянном ответе создания ветки Worker сверяет её с ожидаемым commit SHA; посторонние ветки не перезаписываются. Сохранены CAS, редакторские права и проверки семантики изменений (#615).
- Новые интеграционные тесты проверяют preflight до D1, неопределённые права токена, штатную подготовку резервного PR и восстановление безопасной оставшейся ветки без новых D1 записей.
- Реальный секрет `GITHUB_CATALOG_TOKEN` присутствует в production Worker (подтверждено в GitHub Actions 43723495149); фактическая авторизация/права конкретного значения без owner-сессии не раскрываются публично — проверяются внутри обязательного preflight.
- Не требуется снимать защиты базы, CI и авторизации. Неизвестные новые игровые формулы не объявляются автоматически доказанными.
