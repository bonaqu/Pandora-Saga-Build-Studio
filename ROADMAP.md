# Pandora Saga Build Studio — план разработки

**Updated:** 2026-11-18 · **Latest source release:** 0.901.0 (`2026.11.18.901`)

**Действующие правила:** проверки GitHub Actions — на PR и при публикации, без ежедневных или еженедельных cron-запусков. Для каждой выпускаемой правки обязательны полные Node + Chromium на конкретном SHA, затем проверка GitHub Pages, Worker и опубликованного каталога D1 только на чтение.

## Текущий фокус


0. **Обязательные актуальные игровые данные.** Публичная версия не предлагает архивный режим: работает после подтверждения D1, при обрыве сохраняет локальный черновик и блокирует устаревшие расчёты до безопасной перепроверки или перезагрузки. [Политика онлайн-режима](docs/ONLINE_ONLY_D1_RECOVERY.md). Аудит полноты и устранение регрессий: [#723](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/723).

1. **Управление экипировкой и душами.** Для 8 разрешённых слотов вкладка душ сохраняется даже при вместимости 0, но не позволяет вставлять души. В 0.901.0 совместимые души доступны все без лимита в 80 результатов: компактные порции по 80, сохранение раскрытия при замене души и F5, сброс на новом слоте/поиске, доступность с клавиатуры и RU/EN-подпись через D1. Другие слоты не получают фиктивное управление душами.
2. **Сохранность обновления каталога.** Изменённые игровые записи, неизвестные механики и формулы должны проходить источник-ориентированные проверки; отсутствие доказанного расчёта не подменяется предполагаемым. [Issue #615](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/615) закрыт в GitHub, но это не доказательство полной игровой формульной совместимости будущих данных. Не объявлять неизвестные эффекты проверенными.
3. **Полный охват редактируемых подписей RU/EN.** [Issue #390](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/390) остаётся открытым: проверять оставшиеся пользовательские надписи и подсказки, сохраняя семантические ключи D1. В 0.883.0 закрыт конкретный пробел: 6 заголовков/пояснений групп редактора; общая задача остаётся открытой. Не делать изменяемыми игровые ID, серверные ошибки, секреты, состояние аккаунтов или коэффициенты.
4. **Компактный и понятный интерфейс.** Сохранять оригинальные игровые изображения, единые SVG-иконки и небольшую высоту панелей. Изменение существующего потока не должно незаметно менять текущее состояние героя и сохранённых билдов.

5. **Меньше тестового и DOM-overhead.** В 0.884.0 собраны 47 коротких source-тестов в 5 файлов без удаления проверок. В 0.900.0 D1-подписи индексируются при старте, JSON правки разбирается один раз на refresh и кеш сбрасывается даже при том же объекте overrides после CAS/Undo/Reset. Неизменённые подписи и ARIA не перезаписываются.

6. **Безопасные обновления UI.** Ручное и автоматическое обновление запрещено во время D1-барьера, активных действий, панелей и редактирования владельца; клик не должен даже вызвать `blur` незавершённого поля. Проверка новых версий не дублирует одновременные запросы, включая чтение JSON.

7. **Короткие актуальные правила разработки.** История и отменённые инструкции `AGENTS.md` сохранены без потерь в `docs/history/agents/` с проверкой Git blob SHA. Действующий корневой файл стал компактным, противоречивые старые инструкции не применяются автоматически.

8. **Единое управление усилениями.** В 0.887.0 удалена скрытая устаревшая форма Origin с 20 ненужными DOM-элементами и обработчиками. Все поддерживаемые усиления по-прежнему выбираются и сохраняются только через Книгу героя, без невидимого рендера и лишних расчётов зелий.

9. **Удаление стилей мёртвых компонентов.** В 0.888.0 удалены CSS-селекторы давно отсутствующих скрытых контролов Origin, превью зелий и старой кнопки портрета. Проверяются только реально существующие элементы: общие стили Книги героя, чекбоксы, адаптивная сетка и фокус с клавиатуры.

10. **Библиотека и ссылки.** 0.894–0.900: RU/EN D1-подписи, выбор гостевого/облачного черновика и ленивые подтверждения. Публикация ссылки защищена от повторного POST/GET и смены аккаунта. Перерисовка библиотеки переносит результат на новую карточку без второго запроса; новая сохранённая ревизия не блокируется устаревшей. #390 открыт.

11. **Подтверждение записи и очереди редакторских правок.** В 0.891.0 подтверждение D1-CAS проверяется по ответному ключу, значению и признаку условной записи; неполный HTTP 200 больше не превращается в «Сохранено». Патчи RU/EN одного авторского ключа записываются последовательно, а разные ключи не блокируют друг друга. Чтение игровых каталогов по GET сохраняет массивы JSON без преобразования. Очереди учитываются при Undo/Finish. Включены Node и реальный Chromium регрессионные тесты. Игровые данные и Worker не затрагиваются.

12. **Завершение сохранения и отсутствие лишних перерисовок.** В 0.892.0 индикатор владельца, Undo, EN-переводы и «Завершить» используют одну общую проверку активных и ожидающих D1-операций: очередь RU/EN не отображается как успешно завершённая. Подписи Энциклопедии, экипировки, Origin и библиотеки обновляются точечно без лишних DOM-перезаписей; активные поля сохраняются. В том числе `contenteditable="plaintext-only"` блокирует ручное/автообновление сайта до завершения ввода. Проверки — существующие Node/Chromium; Worker, опубликованный D1 и игровые формулы неизменны.


## Что не требуется от пользователя

Никаких тестов внутри игрового клиента. Подтверждение игрового эффекта — только на основе действующих доступных данных и воспроизводимых источников. Если подтверждения недостаточно, в UI должно быть честное ограничение, а не расчёт наугад.

## Выпуск и проверка

```bash
npm test
npm run test:browser
npm run release:check
```

Сначала проверяем исходный код и регрессии, затем делаем PR. Публикация сайта сама по себе не означает публикацию нового Worker или игрового каталога в D1. Для публикации игровых данных действует отдельная защищённая процедура, только с разрешением на конкретные изменения.

## Редактируемые тексты и обычный режим

Тексты RU/EN имеют стабильные ключи `guideedit.book.*`; сохранённые через редактор изменения загружаются из D1, а встроенные надписи остаются запасными значениями при отсутствии правки. Разметка, CSS, SVG и вычисления остаются в коде. В обычном режиме отсутствуют кнопки администрирования, служебные пояснения о D1/Worker/API и редактируемые карандаши. Скрытый способ открытия инструментов не заменяет серверную авторизацию.
