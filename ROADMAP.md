# Pandora Saga Build Studio — план разработки

**Updated:** 2026-11-20 · **Latest source release:** 0.943.0 (`2026.11.20.943`)

**Действующие правила:** без cron; на каждый PR обязательны Node + Chromium на точном SHA, после публикации — read-only GitHub Pages, Worker и D1.

## Текущий фокус

**0.943 / #390:** В Пути героя редактируются RU/EN формы счётчиков навыков, фрагменты пояснения улучшения 50-го уровня, времени подготовки и подписи навигации. Числа, имена навыков, состояние пользователя и расчётные параметры не попадают в D1 overrides. Видимые подписи имеют inline ✎/F2; ARIA-подписи используют компактный owner-редактор.


**Состояние production D1:** авария [#764](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/764) устранена и закрыта после реальной приёмки: Worker и Pages работают, 16/16 наборов совпадают, исходная точная ошибка квоты не сохранилась. 0.913–0.915 ввели обязательную проверку указателя D1, 24-часовой внутренний snapshot-кэш, coalesced cache misses и Insights без D1-записей. 0.916 защищает клиент от повторных запросов при подтверждённом суточном лимите, но сохраняет немедленную ручную проверку и запрет архивного fallback. Устойчивость при будущей пиковой нагрузке требует сравнимых суточных метрик; процент экономии не выдаётся за доказанный.

0. **Обязательные актуальные игровые данные.** Редактор работает после подтверждения D1; при обрыве сохраняет черновик и блокирует устаревшие расчёты. В 0.905.0 общий загрузчик Энциклопедии отклоняет архивный fallback на публичном хосте даже при ошибке будущего вызывающего кода. Локальные каталоги разрешены только изолированным Node/localhost fixture. [Онлайн-политика](docs/ONLINE_ONLY_D1_RECOVERY.md); исторический [аудит #723](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/723) закрыт.

1. **Экипировка и души.** 8 поддерживаемых типов слотов показывают вкладку душ даже при вместимости 0, но не разрешают вставку. Подходящие души раскрываются порциями по 80, сохраняются при F5; поиск, клавиатура и RU/EN D1 поддержаны. 0.908: единые подсказки вкладок и ПКМ, безопасное нулевое состояние и счётчик полного списка. **0.909:** выбор вещей загружает по 48 без повторного создания карточек и превью, сохраняет раскрытие, запрос и фильтр уровня после F5; завершение перенаправляет фокус. **0.918:** 15 RU/EN D1-подписей у меню ПКМ, навигации по слотам и карточек выбора; имена игровых предметов, уровни и слоты не редактируются. CAS/409/Undo не пересоздают карточки.
2. **Сохранность обновления каталога.** Изменённые игровые записи, неизвестные механики и формулы должны проходить источник-ориентированные проверки; отсутствие доказанного расчёта не подменяется предполагаемым. [Issue #615](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/615) закрыт в GitHub, но это не доказательство полной игровой формульной совместимости будущих данных. Не объявлять неизвестные эффекты проверенными.
3. **Полный охват редактируемых подписей RU/EN.** [Issue #390](https://github.com/bonaqu/Pandora-Saga-Build-Studio/issues/390) остаётся открытым. 0.904–0.906: 35 подписей фильтров, 10 подписей Энциклопедии и прогресс душ доступны через D1 CAS/Undo. Числа результатов, фильтры, имена персонажей, игровые ID, секреты и коэффициенты не редактируются. **0.910:** профиль сохраняет фокус, выделение, парольные поля и авторский статус сообщений при переключении языка; незавершённый inline D1-редактор не удаляется при переводе. **0.917:** сравнение A/B получил девять D1-ключей RU/EN (тексты статусов, заголовок, раскрытие); число отличий и пользовательские имена не редактируются. Проверяются CAS, 409, Undo и сохранность черновика.
4. **Компактный и понятный интерфейс.** Сохранять оригинальные игровые изображения, единые SVG-иконки и небольшую высоту панелей. Изменение существующего потока не должно незаметно менять текущее состояние героя и сохранённых билдов.

5. **Меньше лишнего кода и DOM-операций.** Тестовые контракты объединены (0.884); D1-подписи кешируются и точечно обновляются. Поиск и числовые поля используют общий Yandex autofill guard (0.907) с подтверждением штатных обновлений, без дублирующих обработчиков и принятия посторонних значений.

6. **Безопасные обновления UI.** Ручная и автоматическая установка защищают D1-восстановление, незавершённые действия и ввод. В 0.903.0 реальный режим владельца отделён от сохранения D1: выход убирает старое предупреждение, окончание записи обновляет баннер; проверен первый релиз в браузере без входа в редактор. Версионные запросы объединяются, сохраняют билд и URL.

7. **Короткие актуальные правила разработки.** История и отменённые инструкции `AGENTS.md` сохранены без потерь в `docs/history/agents/` с проверкой Git blob SHA. Действующий корневой файл стал компактным, противоречивые старые инструкции не применяются автоматически.

8. **Библиотека и ссылки.** 0.894–0.900: RU/EN D1-подписи, выбор гостевого/облачного черновика и ленивые подтверждения. Публикация ссылки защищена от повторного POST/GET и смены аккаунта. Перерисовка библиотеки переносит результат на новую карточку без второго запроса; новая сохранённая ревизия не блокируется устаревшей. #390 открыт.

## Что не требуется от пользователя

Никаких тестов внутри игрового клиента. Подтверждение игрового эффекта — только на основе действующих доступных данных и воспроизводимых источников. Если подтверждения недостаточно, в UI должно быть честное ограничение, а не расчёт наугад.

## Выпуск и проверка

```bash
npm test
npm run test:browser
npm run release:check
```

Сначала проверяем исходный код и регрессии, затем делаем PR. Публикация сайта сама по себе не означает публикацию нового Worker или игрового каталога в D1. Для публикации игровых данных действует отдельная защищённая процедура, только с разрешением на конкретные изменения.

## Редактируемые тексты и обычный режим

Тексты RU/EN имеют стабильные ключи `guideedit.book.*`; сохранённые через редактор изменения загружаются из D1, а встроенные надписи остаются запасными значениями при отсутствии правки. Разметка, CSS, SVG и вычисления остаются в коде. В обычном режиме отсутствуют кнопки администрирования, служебные пояснения о D1/Worker/API и редактируемые карандаши. Скрытый способ открытия инструментов не заменяет серверную авторизацию.
