# Pandora Saga Build Studio — CHANGELOG

## 0.918.0 — 2026.11.19.918 · Экипировка: 15 RU/EN-ключей D1 без потери предметов и уровня

- Контекстное меню экипировки (надетая вещь, пустой слот, недоступные души), навигация к соседним слотам, действие выбора/планирования и метаданные карточек предметов получили 15 общих RU/EN-ключей D1. Используется уже существующая компактная секция редактора экипировки и общий CAS/Undo, без новой модалки и карандаша на каждой карточке.
- Условия доступности будущей экипировки и исходное название предмета сохраняются в полном доступном сообщении «Будет доступен с N уровня. Запланировать…»: N и имя собираются из игрового каталога, отдельно от редактируемых текстовых частей. Уровень, ёмкость слотов душ и ID — отдельные нередактируемые узлы.
- После изменения, Undo и сброса D1-копии надписи и aria-label/title обновляются на уже смонтированных кнопках. Не сбрасываются поиск, фильтр, уровень, выбор, страницы списка, выбранная вещь или сохранённый персонаж.
- Расширены существующие Node-контракты и браузерные Chromium-сценарии: гость RU/EN без кнопок админа; владелец RU/EN D1 CAS, конфликт HTTP 409 с сохранённым вводом, Escape/Undo и сохранение тех же DOM-карточек. Изменений Worker, D1-схемы, игрового каталога или формул нет.

## 0.917.0 — 2026.11.19.917 · Сравнение билдов: RU/EN-редактор D1 без потери A/B

- Девять действительно видимых текстов сравнения билдов (заголовок, раскрытие/сворачивание, пустая библиотека, выбор двух билдов, ожидание каталога, ошибка расчёта, отсутствие отличий, префикс счётчика) используют семантические D1-ключи и существующий inline-редактор владельца с CAS/Undo. По умолчанию тексты остаются в исходниках, в D1 сохраняются только редакторские изменения.
- После переключения состояния у кнопки и сообщения меняется текущий ключ без устаревшего карандаша. Активный несохранённый текст сохраняется до окончания CAS и при конфликте 409; успешно сохранённое или отменённое изменение обновляет только живую подпись.
- Динамическое число отличий отрисовывается отдельным текстовым узлом и не становится редактируемым. Сравниваемые характеристики, имена персонажей, сохранённые билды, выбор A/B и игровые формулы не изменяются. Стили сохраняют компактность и не вкладывают кнопки редактора внутрь игровых действий.
- Расширены существующие Node-проверки разрешённых RU/EN-ключей и Chromium-сценарий D1: английская запись, конфликт, Undo, отсутствие сброса несохранённого имени. Полный Node/Chromium CI обязателен. Без Worker-миграций, D1-публикации каталога и тестов игрового клиента.

## 0.916.0 — 2026.11.19.916 · Cloudflare D1: экономные повторные подключения и быстрое ручное восстановление после квоты

- После подтверждённого Cloudflare `D1_DAILY_QUOTA_EXCEEDED` загрузчик читает отдельную копию 503-ответа, сохраняет исходный JSON и не отправляет бессмысленные мгновенные повторы к уже исчерпавшей квоту D1. Простые 503/429, сетевые ошибки и неисправная метка квоты продолжают проходить прежние ограниченные повторы.
- Автоматическое переподключение учитывает серверный `Retry-After`, но не блокируется на целые сутки: пауза ограничена пятью минутами; вход с ручной кнопки и событие восстановления сети выполняют немедленную авторитетную D1-проверку. Только полная проверка снимает блокирующий экран и возвращает работу.
- Скрытая вкладка не выполняет периодические автоматические повторы, а при возвращении на экран восстанавливает попытки. Исходный герой, библиотека, D1-снимок и авторские тексты не подменяются локальным архивом.
- Worker раскрывает через CORS только безопасный HTTP-заголовок `Retry-After`, чтобы браузер GitHub Pages действительно видел время восстановления. Автоматический Worker deploy требует живое подтверждение нового CORS-контракта; без этого браузер получал бы fallback в 60 секунд.
- Расширены существующие Node-тесты и реальный Chromium-сценарий: точное отличие квоты от обычного 503, CORS заголовка, отсутствие повторных проверок при ошибке, поведение focus/visibility, ручное восстановление и сохранение черновика. Нет изменений D1-схемы, данных игры или формул.

## 0.915.0 — 2026.11.19.915 · Cloudflare D1: суточный snapshot-кэш и защита от параллельных чтений

- Подтверждён Cloudflare Insights: в последних 24 часах 4 715 515 строк прочитаны SQL группы `catalog_entries`, в том числе 4 715 422 одним часто выполняемым запросом. Остальные группы существенно меньше; период включает часы до релиза cache 0.913.0. Источник: GitHub Actions #44441285964.
- **Кэш только публичного неизменяемого снимка** хранится во внутреннем Cloudflare Cache API до 24 часов, ключ включает формат сериализации, snapshot и dataset. Внешний HTTP всегда `Cache-Control: no-store`, а D1 `catalog_current` читается заново при каждом запросе. Новая версия каталога получает другой ключ немедленно, при ошибке D1 старый кэш не используется.
- Одновременные запросы при холодном кэше внутри экземпляра Worker разделяют одно чтение D1 и одно наполнение Cache API; каждый получает отдельную копию ответа. HTTP 503/ошибки кешировать запрещено. Проверены гонки, отдельные тела, snapshot-invalidation и отказ кэша.
- Worker deploy теперь требует явных `catalogCacheSingleFlight` и `catalogSnapshotCacheTTLSeconds:86400` в исходнике и в реальном runtime. После успешного релиза read-only Insights показывает последние **1 час**, а не сутки, чтобы отличить расходы после кэширования от исторических. Без миграций/изменений игровых данных.

## 0.914.0 — 2026.11.19.914 · Cloudflare D1: экономная проверка релиза и измерение SQL-строк

- Postmerge приёмка покрывает все 19 наборов D1 без двойного полного скачивания: быстрый smoke проверяет meta/tradeMeta/legacyLocale, затем единственная полная parity-сверка читает оставшиеся 16 наборов и сравнивает содержимое с источником. Ручная команда `connection:check:full` сохранена.
- После **успешной** проверки выполняется Cloudflare D1 Insights через Analytics API, без SQL-запросов к самой D1. Логирует только классы запросов, числа прочитанных/записанных строк и количество выполнений в top-20; сырой SQL, секреты, логины и содержимое билдов не публикует. Итоги top-20 не выдаются за суточное потребление аккаунта.
- При недоступных правах Account Analytics Read отчёт явно сообщает об отсутствии метрик, не блокируя сайт; исходная SQL-диагностика ошибок сохранена для `failure()`. Нет новых cron/CI workflow/миграций. Обновлены существующие тесты и runbook.

## 0.913.0 — 2026.11.19.913 · Оптимизация чтений D1: кэш по снимку, атомарная защита публикации и проверка Worker

- Публичный Worker читает D1-указатель актуального снимка **при каждом** запросе каталога и возвращает внешний ответ с `Cache-Control: no-store` (обычный CDN/браузер не может обойти Worker). Повторные большие ответы из D1 берёт из **внутреннего Cache API** с TTL один час. Ключ содержит версию опубликованного каталога, а не данные пользователя; кешируются только HTTP 200 с `x-ps-catalog: d1` и совпадающим `x-ps-catalog-snapshot`.
- При ошибке указателя D1 сайт получает HTTP 503 без старого кэша/архива. Смена снимка немедленно меняет ключ. При сбое Cache API чтение продолжается напрямую из D1, без потери работоспособности.
- Админский `/api/admin/catalog/batch` отклоняет записи в опубликованный снимок (HTTP 409). Предикат `NOT EXISTS` встроен в сам SQLite INSERT/UPSERT и предотвращает гонку между подготовкой пакета и публикацией. UI продолжает создавать новый случайный снимок для обновления каталога.
- Runtime capabilities и workflow деплоя подтверждают новый snapshot cache при публикации Worker. Расширены существующие Node-тесты: кэш-хит, смена снимка, испорченный кэш, недоступность D1, атомарная гонка и валидный staging; остальной Node/Chromium CI обязателен. Production D1 не изменяли через административные операции, игровой клиент не проверялся.

## 0.912.0 — 2026.11.19.912 · D1: диагностика суточных лимитов и стоимости запросов, сокращение лишних CI-запусков

- GitHub Actions `workflow_run` отфильтрован по ветке ещё до старта workflow: каталогный авто-merge работает только для `catalog/snapshot-ps-*`, зеркалирование оригинальных иконок — только для `bonaqu_projects`. Вторичная проверка ветки внутри jobs сохранена, обязательные Node/Chromium не отключены.
- Расширены существующие контрактные тесты и эксплуатационный runbook. Подозрение на D1 Free row-read cap остаётся гипотезой до прямого подтверждения; никаких откатов Time Travel или архивного режима.

## 0.911.0 — 2026.11.19.911 · Диагностика сбоя D1: безопасная проверка схемы и публикации каталога

- После подтверждённого production-инцидента введена автоматическая диагностика только при неудаче release-readiness: удалённый D1 запрашивается по защищённому точному Cloudflare account/database ID, без D1-записи, восстановления снимков и cron.

## 0.910.0 — 2026.11.19.910 · Аккаунт: сохранение курсора и формы при RU/EN, безопасное завершение D1-редактирования

- Переключение RU/EN в профиле сохраняет активное поле, положение курсора и выделения, прокрутку, раскрытие изменения пароля и введённые значения. Перерисовка не отправляет форму и не раскрывает приватный ввод в хранилище.
- Если во время перевода открыт редактор авторского текста с D1 CAS/Undo, перерисовка профиля откладывается до закрытия редактора вместо потери несохранённого ввода. Повторные переключения не создают конкурирующие обновления.
- Статус сохранения резервного кода больше не превращается в обычное сообщение: редакторский ключ остаётся после переключения RU/EN; серверные ошибки и секреты по-прежнему не редактируются.
- Расширен действующий реальный Chromium-сценарий аккаунта: RU/EN, курсор, приватный ввод, незавершённый редактор и статус восстановления. Игровые формулы, Worker, production D1 не менялись.
- Browser acceptance and deployed Pages state must be verified separately.
