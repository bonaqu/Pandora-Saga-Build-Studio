# Pandora Saga Build Studio — CHANGELOG

## 0.924.0 — 2026.11.19.924 · Энциклопедия переиспользует проверенный D1 snapshot героя

- После успешной загрузки Мастерской уже проверенные D1-наборы `meta`, `items`, `skills`, `souls`, `racialPassives` и `tables` больше не скачиваются повторно при первом открытии Энциклопедии. Запрашиваются только шесть отсутствующих наборов: монстры, локации, подземелья, добыча, обмены NPC и сундуки.
- Переиспользование возможно только для каталога с подтверждённым текущим D1 snapshot и структурной валидацией. Каждый новый GET обязан иметь исходный заголовок D1 и ту же версию. При несовпадении или неполном источнике — отказ вместо архивного fallback. Сохраняется полная финальная проверка связей Wiki.
- Начальный герой, редактирование, RU/EN, account-only библиотека и игровые формулы не меняются. Редакторские overrides продолжают пересобирать локальный индекс без повторных массовых загрузок. Это экономит ровно шесть браузерных запросов к каталогу при типовом входе; экономия запросов непосредственно к SQL D1 не измерялась.
- Дополнены существующие Node-тесты согласованного seed/mismatch/отказа до сети и опубликованный Chromium-сценарий с реальным переходом в Wiki и подсчётом запросов. Полные Node + Chromium и read-only проверка Pages/Worker/D1 обязательны.

## 0.923.0 — 2026.11.19.923 · Путь героя: 11 редактируемых RU/EN-подсказок с D1 CAS/Undo

- Пояснения вложенных очков, зелёного мастерства, заблокированной расовой ветки, общей шкалы и исходных очков получили общие семантические ключи book.path.*. Игровая логика осталась неизменной; редактируется только текст помощи.
- Подписи навигации и ссылок на предыдущие/следующие навыки, а также пояснение дальности от оружия используют те же D1-ключи. Имена навыков и числовые значения являются отдельными неизменяемыми фрагментами.
- Для владельца один сворачиваемый раздел «Подсказки Пути героя» использует общий inline D1 CAS/409/Undo; игроки не видят админских элементов. Изменение подписи обновляет data-help, aria-label и текст уже созданного элемента без сброса поиска и прокачки. RU/EN-переключение не удаляет открытый редактор.
- Расширены существующие Node-тесты ключей и неизменности игровых имён, а также Chromium-сценарий владельца с RU/EN CAS. Без изменений Worker, D1-схемы, формул и игровых ресурсов.

## 0.922.0 — 2026.11.19.922 · D1: отмена устаревших Wiki-пакетов и фоновых проверок

- При изменении опубликованного каталога или авторских D1-правок Энциклопедия прекращает старую группу запросов. Новая загрузка не ждёт устаревших GET и повторно проверяет единый snapshot.
- Ограниченный публичный загрузчик принимает внешний AbortSignal; внутреннее прерывание соседних запросов при сетевом отказе, три одновременных набора и сохранение первоначальной ошибки не ослаблены. Отмена никогда не превращается в публичный архивный fallback.
- D1 heartbeat прерывается при offline и скрытии вкладки, а при возвращении выполняется свежая проверка; поздний ответ не может разблокировать либо ложно заблокировать редактор. Скрытый focus не делает сетевых GET.
- Добавлены реальные асинхронные регрессии в существующие Node-наборы: отмена трёх активных запросов, pre-abort, отсутствие локального fallback и поздний checkpoint. Обязательны полный Node/Chromium CI и post-merge read-only приёмка. Worker, D1-схема, игровые формулы и пользовательские билды не менялись.

## 0.921.0 — 2026.11.19.921 · Энциклопедия: D1 пакет с ранней проверкой snapshot и общей отменой

- Общий лимит в три параллельных запроса Энциклопедии теперь использует сигнал отмены всей пачки: при недоступном, неподтверждённом или повреждённом наборе оставшиеся загрузки прекращаются, следующие не отправляются.
- D1-происхождение, отсутствие snapshot и расхождение версий проверяются сразу по заголовку каждого из 12 обязательных наборов, до загрузки остальных JSON; итоговая строгая проверка каталога остаётся обязательной.
- Локальные тестовые fixture и исторические языковые описания сохраняют прежние ограничения; публичный архивный fallback не разрешается. Игровые данные, формулы, записи D1, авторские overrides и сохранённые билды не изменялись.
- Регрессии добавлены к существующим Node-наборам, включая реальную общую отмену и раннее выявление split-snapshot. Полный Node/Chromium CI и финальная проверка production D1 только на чтение обязательны.

## 0.920.0 — 2026.11.19.920 · D1: ранняя проверка snapshot и отмена соседних загрузок

- При ошибке любого из девяти обязательных наборов каталога больше не продолжаются остальные параллельные GET: общий AbortSignal останавливает соседние загрузки и исключает старт новых. Сохраняется первая реальная причина сбоя.
- Отсутствие D1 snapshot и разные snapshot выявляются непосредственно при получении заголовка каждого набора, до разбора очередных крупных JSON и публикации в редакторе.
- Публичный GET теперь подчиняется AbortSignal и таймауту даже при зависшем стороннем HTTP-адаптере. Аналогично отменяется зависший разбор кода исчерпанной квоты; устаревший ответ не создаёт ложный cooldown.
- Расширены существующие Node-тесты: зависший fetch, таймаут, поздний ответ quota, групповой abort и порядок результатов. Полный Chromium и Node обязательны на HEAD PR. Без изменений формул, аккаунтов, D1-схемы, слотов, переводов или пользовательских билдов.

## 0.919.0 — 2026.11.19.919 · Сетевой checkpoint: отмена устаревших запросов и фоновых опросов

- Повторные публичные D1 GET прекращаются немедленно при отмене запроса во время HTTP 429/503 и сетевого backoff. Для штатного ожидания освобождается таймер; пользовательские задержки в тестовых адаптерах также не могут удерживать отменённый запрос.
- Проверка обязательного D1-snapshot повторно учитывает AbortSignal после обоих HTTP-ответов и разбора JSON. Даже fetch/JSON-адаптер, проигнорировавший отмену, не разблокирует устаревшие игровые данные.
- Опрос новой версии Pages прекращён в скрытых вкладках; при уходе вкладки отменяется активный запрос, а при возврате выполняется новая проверка. Поздний ответ скрытой вкладки не показывает баннер новой версии.
- Расширены существующие Node-регрессии: остановка повторных GET после отмены, поздний D1 checkpoint, фоновые проверки версии и отказ от устаревшего баннера. Игровые формулы, аккаунты, D1-схема и production-записи не изменены. Полные Node/Chromium CI и опубликованный сайт проверяются отдельно.

## 0.916.0 — 2026.11.19.916 · Cloudflare D1: экономные повторные подключения и быстрое ручное восстановление после квоты

- После подтверждённого Cloudflare `D1_DAILY_QUOTA_EXCEEDED` загрузчик читает отдельную копию 503-ответа, сохраняет исходный JSON и не отправляет бессмысленные мгновенные повторы к уже исчерпавшей квоту D1. Простые 503/429, сетевые ошибки и неисправная метка квоты продолжают проходить прежние ограниченные повторы.
- Автоматическое переподключение учитывает серверный `Retry-After`, но не блокируется на целые сутки: пауза ограничена пятью минутами; вход с ручной кнопки и событие восстановления сети выполняют немедленную авторитетную D1-проверку. Только полная проверка снимает блокирующий экран и возвращает работу.
- Скрытая вкладка не выполняет периодические автоматические повторы, а при возвращении на экран восстанавливает попытки. Исходный герой, библиотека, D1-снимок и авторские тексты не подменяются локальным архивом.
- Worker раскрывает через CORS только безопасный HTTP-заголовок `Retry-After`, чтобы браузер GitHub Pages действительно видел время восстановления. Автоматический Worker deploy требует живое подтверждение нового CORS-контракта; без этого браузер получал бы fallback в 60 секунд.
- Расширены существующие Node-тесты и реальный Chromium-сценарий: точное отличие квоты от обычного 503, CORS заголовка, отсутствие повторных проверок при ошибке, поведение focus/visibility, ручное восстановление и сохранение черновика. Нет изменений D1-схемы, данных игры или формул.

## 0.915.0 — 2026.11.19.915 · Cloudflare D1: суточный snapshot-кэш и защита от параллельных чтений

- Подтверждён Cloudflare Insights: в последних 24 часах 4 715 515 строк прочитаны SQL группы `catalog_entries`, в том числе 4 715 422 одним часто выполняемым запросом. Остальные группы существенно меньше; период включает часы до релиза cache 0.913.0. Источник: GitHub Actions #44441285964.
- **Кэш только публичного неизменяемого снимка** хранится во внутреннем Cloudflare Cache API до 24 часов, ключ включает формат сериализации, snapshot и dataset. Внешний HTTP всегда `Cache-Control: no-store`, а D1 `catalog_current` читается заново при каждом запросе. Новая версия каталога получает другой ключ немедленно, при ошибке D1 старый кэш не используется.
- Одновременные запросы при холодном кэше внутри экземпляра Worker разделяют одно чтение D1 и одно наполнение Cache API; каждый получает отдельную копию ответа. HTTP 503/ошибки кешировать запрещено. Проверены гонки, отдельные тела, snapshot-invalidation и отказ кэша.
- Worker deploy теперь требует явных `catalogCacheSingleFlight` и `catalogSnapshotCacheTTLSeconds:86400` в исходнике и в реальном runtime. После успешного релиза read-only Insights показывает последние **1 час**, а не сутки, чтобы отличить расходы после кэширования от исторических. Без миграций/изменений игровых данных.

## 0.914.0 — 2026.11.19.914 · Cloudflare D1: экономная проверка релиза и измерение SQL-строк

- Postmerge приёмка покрывает все 19 наборов D1 без двойного полного скачивания: быстрый smoke проверяет meta/tradeMeta/legacyLocale, затем единственная полная parity-сверка читает оставшиеся 16 наборов и сравнивает содержимое с источником. Ручная команда `connection:check:full` сохранена.
- После **успешной** проверки выполняется Cloudflare D1 Insights через Analytics API, без SQL-запросов к самой D1. Логирует только классы запросов, числа прочитанных/записанных строк и количество выполнений в top-20; сырой SQL, секреты, логины и содержимое билдов не публикует. Итоги top-20 не выдаются за суточное потребление аккаунта.
- При недоступных правах Account Analytics Read отчёт явно сообщает об отсутствии метрик, не блокируя сайт; исходная SQL-диагностика ошибок сохранена для `failure()`. Нет новых cron/CI workflow/миграций. Обновлены существующие тесты и runbook.

## 0.913.0 — 2026.11.19.913 · Оптимизация чтений D1: кэш по снимку, атомарная защита публикации и проверка Worker

- Публичный Worker читает D1-указатель актуального снимка **при каждом** запросе каталога и возвращает внешний ответ с `Cache-Control: no-store` (обычный CDN/браузер не может обойти Worker). Повторные большие ответы из D1 берёт из **внутреннего Cache API** с TTL один час. Ключ содержит версию опубликованного каталога, а не данные пользователя; кешируются только HTTP 200 с `x-ps-catalog: d1` и совпадающим `x-ps-catalog-snapshot`.
- При ошибке указателя D1 сайт получает HTTP 503 без старого кэша/архива. Смена снимка немедленно меняет ключ. При сбое Cache API чтение продолжается напрямую из D1, без потери работоспособности.
- Админский `/api/admin/catalog/batch` отклоняет записи в опубликованный снимок (HTTP 409). Предикат `NOT EXISTS` встроен в сам SQLite INSERT/UPSERT и предотвращает гонку между подготовкой пакета и публикацией. UI продолжает создавать новый случайный снимок для обновления каталога.
- Runtime capabilities и workflow деплоя подтверждают новый snapshot cache при публикации Worker. Расширены существующие Node-тесты: кэш-хит, смена снимка, испорченный кэш, недоступность D1, атомарная гонка и валидный staging; остальной Node/Chromium CI обязателен. Production D1 не изменяли через административные операции, игровой клиент не проверялся.
